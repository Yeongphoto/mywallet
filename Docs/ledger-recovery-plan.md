# 장부 연결 해제·초기화 보존 및 7일 복구 계획

> 2026-10-21: 아래는 구현 전 조사·설계 기록이다. 현재 구현과 사용 방법, 용량 제한 및 검증은 [장부 복구](ledger-recovery.md)를 따른다. 연결 끊기의 무기한 원본 보존 동작은 유지한다.

## 이번 작업에서 확인한 현재 동작

- 설정의 장부 **연결 끊기**는 `selectWallet('local')`로 `/guest#settings`를 여는 기기 모드 전환이다. 로그아웃·공유 탈퇴·장부 삭제·초기화 API를 호출하지 않는다.
- 서버의 장부 ID, 원본 데이터, 호스트/게스트 참여 권한은 그대로 남는다. 개인·공유 장부 모두 같은 Google 계정으로 로그인한 뒤 장부 선택에서 다시 열 수 있다. 이 동작에는 7일 제한이 없다.
- 계정·장부별 캐시와 보류 작업 키도 삭제하지 않는다. 로컬 장부는 별도 저장 공간을 사용하며 클라우드 원본을 복사하거나 덮어쓰지 않는다. 연결 끊기 확인창에서 이 차이를 안내한다.
- 공유 멤버 제거 API는 호스트 본인 제거를 `OWNER_CANNOT_LEAVE`로 거부하고, `role<>'owner'` 조건으로 소유권을 보호한다. 연결 끊기는 이 API와 별개다.
- 현재 설정의 데이터 화면에는 사용 가능한 전체 초기화 버튼이 없다. `App.tsx`의 기존 `handleReset`은 호출되지 않는 과거 코드다. 클라우드 전체 스냅샷 저장기도 현재 no-op이므로 이를 연결해 초기화 성공으로 표시해서는 안 된다.
- 아직 **초기화/장부 삭제 후 7일 복구 API·보관함·예약 파기 작업은 구현되지 않았다.** 실제 기능이 갖춰지기 전에는 사용자에게 “7일 이내 복구 가능”을 보장하는 문구나 초기화 버튼을 노출하지 않는다.

## 이번 작업 검증

현재 UI 검증에서는 모의 API와 독립 브라우저를 사용해 확인창 취소, 로컬 전환, 동일 공유 장부 재연결을 실행했다. 클라우드 거래·기존 로컬 거래·백업 표식과 호스트 표시가 유지되고 삭제·탈퇴·로그아웃 요청이 발생하지 않는 것을 확인했다. `npm run check:auth`의 48개 검사에도 호스트 본인 제거 거부와 사용자별 캐시 격리가 포함되어 통과했다. 실제 사용자 장부를 초기화하거나 삭제하는 테스트는 하지 않았다.

## 다음 구현의 범위

연결 끊기는 기존의 안전한 기기 전환으로 유지한다. 별도 동작인 개인 장부 초기화와 공유 장부 보관/삭제에 복구 기간을 도입한다. 호스트가 기기를 바꾸거나 연결을 끊었다고 공유 장부를 보관·삭제하지 않는다. 게스트의 연결 해제도 다른 사용자의 접근에 영향을 주지 않는다.

### 개인 장부 초기화

1. 서버가 소유자 재인증, 현재 장부 ID·변경 버전, 중복 방지 operation ID를 검증한다. 저장 중·보류 작업·충돌이 있으면 먼저 해결하고 진행한다.
2. 서버에 전체 스냅샷과 manifest를 보관한다. 거래, 자산, 카드 정산, 예산, 계획, 카테고리, 색·이름·제외·숨김 설정, 정기 규칙, 삭제된 정기기록 ID, 정렬/버전 메타데이터를 함께 담는다. DB 간 스냅샷의 변경 버전이 일치하지 않으면 중단한다.
3. 저장 완료 후 건수·해시·복원 검증까지 성공해야 초기화를 허용한다. 백업/용량/네트워크 오류는 초기화보다 먼저 실패해야 한다. localStorage만의 사본이나 CSV만으로 복구를 보장하지 않는다.
4. 비어 있는 새 활성 세대(generation)를 만들고, 이전 세대는 7일 동안 복구 전용으로 보존한다. 기존 세대의 지연된 저장·재시도·오프라인 작업은 새 장부에 적용되지 않도록 세대 ID를 검증한다. 장부 ID와 소유권은 유지한다.
5. `설정 → 데이터 → 최근 초기화 복구`에서 만료 시각과 대상을 확인한다. 초기화 이후 새 기록이 있으면 덮어쓰지 않고 먼저 별도 보관한 뒤 사용자가 명시적으로 복원한다. 같은 복원 요청의 재시도는 한 번만 적용한다.

### 공유 장부 보관/삭제

- 호스트만 보관 또는 삭제 예약을 요청한다. 호스트 계정·참여 권한·초대 관계와 장부 UUID를 유지한 채 `active → recoverable → active/expired` 상태로 관리한다.
- 보관 시작 시 모든 멤버의 쓰기를 차단하고 멤버에게 같은 상태를 보여준다. 복구하면 같은 UUID·역할·데이터로 재개한다. 새 장부 생성으로 소유 장부 개수 제한을 우회하지 못하게 한다.
- 게스트의 탈퇴/내 기기 연결 해제는 장부 삭제 예약을 생성하지 않는다. 호스트 소유권을 자동으로 해제하거나 다른 계정으로 넘기지 않는다.

### 보존 데이터와 서버 규칙

- 인증 DB의 복구 메타데이터 예시: `recovery_id`, `ledger_id`, `owner_user_id`, `kind`, `source_generation`, `state`, `created_at`, `expires_at`, `operation_id`, `manifest_hash`, `restored_at`.
- 서버 UTC 시각 기준으로 생성 시각부터 7×24시간을 보장한다. 복원 요청은 권한과 만료 시각을 **실행 시점에도** 다시 검사하고 원자적으로 상태를 전환한다.
- 메타데이터와 금융 스냅샷은 별도 DB일 수 있으므로 단계별 완료 표식·재시도·변경 차단이 필요하다. 스냅샷 저장만 성공하고 초기화가 실패한 경우에도 활성 원본은 손상되지 않아야 한다.
- 만료 후 파기는 별도 작업이 권한·진행 상태·기준 시각을 확인한 뒤 수행한다. 복원 중인 스냅샷이나 활성 세대는 지우지 않으며 파기 이력을 남긴다. 사용자가 접속하지 않아도 보존 기한이 올바르게 처리되어야 한다.
- 계정 없는 로컬 장부는 기기 저장 공간에 의존하므로 서버와 같은 보장을 단정하지 않는다. IndexedDB 복구 스냅샷의 실제 저장·검증에 성공한 경우에만 기기 내 복구를 안내한다. 앱 삭제·사이트 데이터 삭제 시에는 별도 외부 백업이 필요하다.

## 구현 완료 후 표시할 안내

- 초기화: “현재 장부를 초기화합니다. 초기화 전 기록은 7일 동안 보관되며 설정에서 복구할 수 있어요.” 정확한 만료 일시도 함께 표시한다.
- 공유 장부 삭제 예약: “장부가 보관 상태로 바뀌며 함께 쓰는 사람의 이용이 중단됩니다. 7일 안에 호스트가 복구할 수 있어요.”
- 연결 끊기: 현재처럼 서버 원본·권한이 유지되고 언제든 다시 선택할 수 있다고 안내한다. 7일 제한과 혼동시키지 않는다.

## 배포 전 필수 검증

소유자/게스트 권한, 백업 저장 실패 시 원본 보존, 전체 필드 round-trip, 복원 이후 새 기록 보존, 7일 경계·UTC·중복 요청, 동시 수정, 여러 기기의 오프라인 재시도와 세대 차단, 공유 장부 개수 제한, 로컬 용량 초과, 만료 파기와 복원의 경합을 격리된 테스트 DB에서 검증한다. 기존 웹앱 DB에는 적용하지 않는다. 서버 복구 기능이 배포되고 실제 복원이 검증된 뒤 초기화 버튼과 7일 안내를 활성화한다.
