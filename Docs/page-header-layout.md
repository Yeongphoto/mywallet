# 고정 브랜드 헤더

공유 장부 관리, 계정 관리, 통합 자산/거래 등록 화면에 메인과 같은 초록 배경·Memoney 로고·고정 상단 구성을 요청했다. 거래 수정창도 같은 입력 화면 규칙을 적용한다.

`AppPageHeader`가 기존 `BrandWordmark main`과 `--family-mint / --family-toolbar` 색상을 재사용한다. 기존 설치 아이콘·원본 로고·스플래시·로딩 렌더러는 수정하지 않는다. 브랜드 줄은 메인과 같은 32px/124px 로고, 제목·뒤로가기/닫기 줄은 56px로 합계 88px이며 기기 상단 안전 여백은 한 번만 더한다. 라이트/다크·기본/테마1의 기존 색상과 모양 규칙을 따른다.

페이지 본문은 고정 헤더 아래에서 시작한다. 공유 관리 화면의 기존 작은 우측 고양이 로고는 중복 표시하지 않는다. 계정 관리의 뒤로가기는 기존 선택 경로를 유지하며 공유/가입/계정 권한을 바꾸지 않는다. 이름 ‘변경’ 버튼은 줄바꿈 없이 표시한다.

등록·수정창은 같은 헤더를 바깥 고정 영역에 두고 기존의 단일 스크롤 뷰포트에서 헤더 높이를 제외한다. 헤더를 클릭해도 바깥 배경 닫기로 전파하지 않고, 닫기 버튼은 기존 취소 경로를 사용한다. 키보드 여백과 입력창 노출 처리는 기존 useEntryViewport를 유지한다.

후속 높이 보정: 모바일 폼의 최소 높이도 헤더를 제외한 본문 높이에 맞춘다. 이전에는 뷰포트에서만 헤더를 제외하고 폼은 화면 전체 높이를 요구해 빈 공간이 있어도 헤더 높이만큼 스크롤됐다. 필드 높이는 본문 높이에 비례해 48~88px, 필드 및 버튼 앞 간격은 6~12px로 조절한다. 여유 공간에서는 버튼을 아래에 배치하고 긴 메모·추가 필드·키보드가 실제 공간을 넘을 때는 바깥 스크롤을 유지한다. 키보드 노출만으로 필드가 다시 작아지지 않도록 기존의 고정된 화면 높이 계산을 사용한다. 등록·수정창에 같은 규칙을 적용하며 헤더는 그대로 유지한다.

후속 검증 `node scripts/check-entry-height.mjs`: 320×568, 411×560, 768×560, 411×900에서 라이트/다크·기본/테마1·등록 네 종류를 조합한 64건을 검사한다. 상단 안전 여백 24px를 포함해 헤더 아래 시작, 빈 폼의 불필요한 스크롤 없음, 하단 버튼 노출, 최소 터치 높이와 높이별 간격을 확인한다. 금융 API 요청은 0건이다.

헤더 버튼 내부 정렬: 뒤로가기와 닫기는 글꼴의 기준선·문자 여백 영향을 받는 `‹`/`×` 대신 24px SVG를 사용한다. 화살표와 X 경로 자체의 바운딩 박스 중심을 viewBox 중앙에 맞추고 flex 중앙 정렬·블록 SVG로 배치한다. 기존 44×44px 버튼 영역과 위치·클릭 동작은 유지한다. `check-page-action-centers.mjs`는 실제 경로의 getBBox 중심을 화면 좌표로 변환해 버튼 중심과 0.1px 이내인지 검사한다. 등록 네 종류 64개 조합과 계정/공유 관리의 라이트·다크·두 스타일에서 검증하며 추가 !important는 사용하지 않는다.

검증: production 빌드, 등록·수정 레이아웃 48개 조합(필드/버튼 크기·간격/취소/명시적 저장), 회원·공유 UI 8개 조합(고정 로고/스크롤/뒤로가기/권한 표시/관리), 가이드 16개 조합을 통과했다. 24px 상태바 여백에서 헤더가 정확히 112px이고, 키보드 모의 노출 후에도 필드 크기와 브랜드 위치가 유지되는 것을 확인했다. 격리 로컬 장부와 API 모의 응답을 사용했으며 금융 API 쓰기는 0건이다. Orca의 계정 관리 모의 화면에서도 고정 브랜드·제목 영역을 확인했다.
