# 거래 입력창과 키보드

등록·수정은 키보드 유무와 관계없이 하나의 자연 높이 레이아웃을 사용한다. `entry-dialog-viewport` 하나만 모달 바깥에서 스크롤하며, modal-body·form·form-grid는 별도 스크롤·최대 높이·고정 프레임을 갖지 않는다. 헤더·입력칸·버튼은 모두 같은 흐름에 있고 키보드가 열려도 상대 위치를 바꾸지 않는다. 키보드가 가리는 부분은 폼 전체를 바깥 스크롤로 이동해 본다.

키보드 전환 중 배경 노출 대응: 바깥 `entry-dialog-backdrop`은 화면 전체를 불투명하게 덮고 크기·투명도 애니메이션을 하지 않는다. 안쪽 `entry-dialog-viewport`만 키보드 높이에 맞춘다. 실기기 에뮬레이터에서 visual viewport가 순간적으로 578→242→578px로 보고되는 것을 기록했으므로 resize 값은 80ms 안정화 후 반영한다. 모달의 등장 transform·배경 blur도 이 두 입력 창에서는 사용하지 않는다. 검증에 전체 배경 덮임, 순간 절반 높이 값 무시, 실제 키보드 프레임별 위치 기록을 포함한다.

포커스 시 문서 전체의 `scrollIntoView`를 호출하지 않는다. 입력칸이 가시 영역을 벗어난 경우에만 바깥 스크롤의 `scrollTop`을 보정한다. 같은 높이·위치 값은 다시 쓰지 않고 추천창 좌표도 같으면 React state를 유지한다. 내용 입력칸의 배경·테두리·그림자와 버튼의 변형·밝기 효과는 포커스 여부로 변하지 않는다.

`useEntryViewport`는 키보드를 제외한 `visualViewport.height`와 `offsetTop`을 바깥 스크롤 영역에만 전달한다. 모달이나 폼의 높이를 계산하지 않으며 `--entry-layout-height` 고정 프레임도 사용하지 않는다.

이전 기록 추천은 `FloatingTitleSuggestions`를 통해 폼 밖의 body에 포털로 띄운다. 키보드를 제외한 보이는 영역에서 입력칸 아래 공간을 확인하고 부족하면 위로 띄운다. 제목·종류 탭과 등록 버튼을 피하고, 폼 스크롤·키보드·창 크기 변경 시 위치를 다시 계산한다. 입력칸 높이는 추천 목록과 무관하게 유지한다. 포털 안의 터치는 외부 클릭 닫기에서 제외하며 포인터 포커스 보호와 클릭 선택을 사용한다. 거래 선택 시 기존 제목·카테고리 적용 규칙은 유지한다.

입력칸과 등록·수정 버튼은 48px, 글자는 1rem 기준으로 유지한다. 버튼도 일반 흐름에 있어 키보드 위로 별도 재배치하지 않는다. 추천 목록의 터치 드래그 스크롤은 독립적으로 유지한다.

제목줄은 패밀리 민트색, 닫기는 카드색으로 바꾸고 다크 모드 글자색을 함께 맞춘다. 기본·테마1 모두 적용하되 모서리 스타일은 각 테마를 따른다.

검증은 격리한 기기 장부 fixture에서 폰·펼친 폴드 폭, 라이트·다크, 기본·테마1의 8개 조합으로 수행한다. 실제 브라우저 viewport 높이를 900→440/380으로 변경해 입력칸·종류 탭·등록 버튼의 폭·높이·글자 크기·패딩이 같은지 비교한다. 등록·수정 플로팅 추천 위치와 터치 선택·목록 터치 스크롤, 창 취소 후 거래·자산·예산·updatedAt 보존, 금융 API 쓰기 0회를 확인한다. 저장·동기화 로직과 기존 웹 DB는 변경하지 않는다.
