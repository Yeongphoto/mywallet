# 거래 입력창과 키보드

2026-10-17 사용자 요청으로 휴대폰 등록은 웹앱처럼 전체 화면으로 복원했다. 768px 이하에서는 창 테두리·바깥 여백·둥근 창 모서리가 없고, 취소·등록을 기본 화면의 하단에 배치한다. 폴드·PC는 최대 640px의 중앙 모달이다. 수정 모달은 자연 높이를 유지한다.

키보드 유무와 관계없이 폼 배치를 유지한다. `entry-dialog-viewport` 하나만 스크롤하며 modal-body·form·form-grid는 별도 스크롤·최대 높이를 갖지 않는다. 키보드가 열리면 바깥 그리드의 두 번째 행에 키보드 높이만큼 스크롤 공간을 추가한다. 첫 번째 행과 폼은 키보드 전 화면 높이를 유지하므로 입력칸과 버튼의 상대 위치·크기를 바꾸지 않는다. 하단 버튼은 화면 전체를 스크롤해 접근한다. 키보드 위로 버튼만 따로 재배치하지 않는다.

키보드 전환 중 배경 노출 대응: 바깥 `entry-dialog-backdrop`은 화면 전체를 불투명하게 덮고 크기·투명도 애니메이션을 하지 않는다. 안쪽 `entry-dialog-viewport`만 키보드 높이에 맞춘다. 실기기 에뮬레이터에서 visual viewport가 순간적으로 578→242→578px로 보고되는 것을 기록했으므로 resize 값은 80ms 안정화 후 반영한다. 모달의 등장 transform·배경 blur도 이 두 입력 창에서는 사용하지 않는다. 검증에 전체 배경 덮임, 순간 절반 높이 값 무시, 실제 키보드 프레임별 위치 기록을 포함한다.

포커스 시 문서 전체의 `scrollIntoView`를 호출하지 않는다. 입력칸이 가시 영역을 벗어난 경우에만 바깥 영역을 부드럽게 스크롤한다. 모션 줄이기 설정에서는 즉시 이동한다. 글자를 입력할 때마다 스크롤을 다시 시작하지 않는다. 같은 높이·위치 값은 다시 쓰지 않고 추천창 좌표도 같으면 React state를 유지한다. 내용 입력칸의 배경·테두리·그림자와 버튼의 변형·밝기 효과는 포커스 여부로 변하지 않는다.

`useEntryViewport`는 화면 높이 `--entry-screen-height`, 가시 영역 높이·위치, 키보드 여유 `--entry-keyboard-inset`를 전달한다. 편집 가능한 입력에 포커스가 있고 가시 높이가 100px 이상 줄면 키보드로 판단한다. 키보드가 닫히거나 창 폭이 바뀌면 기준 높이를 다시 측정한다. 키보드 전환 중에는 기준 화면 높이를 줄이지 않는다.

이전 기록 추천은 `FloatingTitleSuggestions`를 통해 폼 밖의 body에 포털로 띄운다. 키보드를 제외한 보이는 영역에서 입력칸 아래 공간을 확인하고 부족하면 위로 띄운다. 제목·종류 탭과 등록 버튼을 피하고, 폼 스크롤·키보드·창 크기 변경 시 위치를 다시 계산한다. 입력칸 높이는 추천 목록과 무관하게 유지한다. 포털 안의 터치는 외부 클릭 닫기에서 제외하며 포인터 포커스 보호와 클릭 선택을 사용한다. 거래 선택 시 기존 제목·카테고리 적용 규칙은 유지한다.

휴대폰 등록 입력칸과 버튼은 키보드 전 화면 높이의 9.5%를 기준으로 52~88px 범위에 맞춘다. 900px 화면에서는 웹앱과 같은 85.5px이며 키보드가 열려도 바뀌지 않는다. 폴드·PC와 수정은 48px 기준이다. 글자는 1rem 기준으로 유지한다. 추천 목록의 터치 드래그 스크롤은 독립적으로 유지한다.

제목줄은 패밀리 민트색, 닫기는 카드색으로 바꾸고 다크 모드 글자색을 함께 맞춘다. 기본·테마1 모두 적용하되 모서리 스타일은 각 테마를 따른다.

플로팅은 외곽 박스 하나 안에 평평한 행과 얇은 구분선만 둔다. 행별 테두리·둥근 박스·그림자와 분류 배지를 감싸는 박스는 사용하지 않는다. 등록·수정 버튼은 폼의 `data-entry-type`을 따라 지출 빨강·수입 파랑·이체 보라·자산 초록으로 표시한다. 선택 탭과 등록 버튼은 같은 action 배경 토큰을 사용하며, 흰 글자와의 대비를 4.5:1 이상으로 확인한다. 자산은 기존 `--asset-action-bg`를 유지한다.

검증은 격리한 기기 장부 fixture에서 폰·펼친 폴드 폭, 라이트·다크, 기본·테마1의 8개 조합으로 수행한다. 내용에 포커스한 뒤 브라우저 viewport 높이를 900→440/380으로 변경해 키보드를 모의한다. 입력칸·종류 탭·등록 버튼의 폭·높이·글자 크기·패딩·폼 내부 상대 위치가 같고 스크롤 공간이 늘어나는지 확인한다. 등록·수정 플로팅 추천 위치와 터치 선택·목록 터치 스크롤, 창 취소 후 거래·자산·예산·updatedAt 보존, 금융 API 쓰기 0회를 확인한다. 저장·동기화 로직과 기존 웹 DB는 변경하지 않는다.

실제 Android 에뮬레이터에서도 확인했다. 미디움폰은 키보드 전후 모달 높이 914.29px·입력칸 높이 86.86px를 유지하고 하단 여유 336.38px를 추가했다. 펼친 폴드는 모달 높이 476px·입력칸 48px를 유지하고 여유 288px를 추가했다. 두 기기 모두 폼 전체가 이동해 내용칸이 키보드 위에 보였다. 휴대폰의 상태 표시줄 영역은 고정 배경으로 덮어 스크롤되는 탭과 겹치지 않도록 한다.
