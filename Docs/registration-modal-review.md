# 웹앱 등록 모달 비교 점검

점검일: 2026-10-17. 앱 기준 커밋은 `087fa38`이며 점검 시작 시 미커밋 변경은 없었다.

## 확인 방법

- 실제 웹 배포 `https://mywallet-8mx.pages.dev`의 등록 모달을 411×900, 1024×900, 1280×900 화면에서 확인했다. 확인한 진입 번들은 `index-DXdPl7K0.js`다.
- 별도 브라우저 프로필에서 모든 `/api/` 요청을 검토용 응답으로 대체했다. 실제 장부 조회·쓰기 요청은 서버에 보내지 않았고 쓰기 시도도 0회였다. 저장 버튼은 누르지 않았다.
- 금액 계산기, 분류 선택, 자산 선택 팝업을 열고 닫았다. 검토용 거래 한 건으로 내용 이력 표시와 선택을 확인했다.
- `agy` 소스와 현재 브랜치의 `UnifiedEntryForm`, 등록 모달, CSS를 비교했다. 소스 비교 기준을 실제 배포 커밋과 동일하다고 단정하지 않는다.
- 화면 높이 변경은 브라우저 모의 환경이다. 실제 Android IME 동작을 검증한 결과로 취급하지 않는다.

## 기존 웹앱의 사용 방식

| 항목 | 실제 웹앱 | 현재 Android 브랜치 |
| --- | --- | --- |
| 휴대폰 등록 화면 | 화면 전체를 채움. 411×900에서 모달도 411×900 | 위쪽에 자연 높이의 창. 좌우 12px 여백, 최대 640px |
| 폴드·PC | 가운데 배치한 640px 모달. 1024·1280 폭에서 높이 469px | 위쪽 배치, 화면 바깥 스크롤 영역 사용 |
| 입력 배치 | 날짜·시간 한 줄 → 금액 → 카테고리 → 자산 → 내용 | 같은 순서 유지 |
| 휴대폰 입력 크기 | 900px 높이에서 입력칸과 하단 버튼 85.5px | 입력칸·하단 버튼 48px |
| 하단 동작 | 취소·등록 두 버튼. `sticky`로 하단 유지 | 입력 폼 다음 일반 흐름에 배치 |
| 스크롤 | 모달 본문·입력 그리드의 스크롤 및 추천 표시 시 overflow 전환 | 모달 바깥 `entry-dialog-viewport` 하나만 스크롤 |
| 내용 이력 | 내용칸 아래에 붙는 절대 위치 목록 | body 포털에서 가용 공간에 따라 위·아래로 배치 |
| 이력 선택 | 제목 적용. 분류가 비어 있을 때만 기존 기록의 분류 적용 | 같은 적용 규칙. 터치 처리를 pointer/click으로 변경 |
| 색상 | 지출 빨강·수입 파랑·이체 보라·자산 초록 | 의미색 유지. 글자 대비를 위해 강조색 조정 |

금액은 시스템 키보드 대신 앱 계산기로 입력한다. 계산기 완료는 미입력 상태에 따라 분류 → 자산 → 내용으로 이어지는 흐름이다. 이체는 출금 자산 → 입금 자산 → 내용 순서다. 날짜·시간도 전용 선택기를 사용한다. 정기/할부는 금액칸의 보조 버튼으로 연다. 현재 코드에서도 이 순서와 검증 흐름은 유지되어 있다.

내용 이력은 검토용 `검토용 커피`를 선택했을 때 제목과 비어 있던 분류 `생필품`이 적용되는 것을 확인했다. 이미 선택한 분류를 유지하는 조건은 소스에서 확인했다. 자산이 없는 검토 데이터에서는 자산 선택기에 빈 상태 안내가 표시되었다. 실제 자산 선택과 등록 저장까지 검증한 것은 아니다.

## 복원 기준

1. 휴대폰은 전체 화면, 폴드·PC는 가운데 모달이라는 웹앱 구조를 복원한다.
2. 입력 순서·계산기·날짜/시간·분류/자산 선택·정기/할부·내용 이력의 적용 규칙을 웹앱과 맞춘다.
3. 취소·등록은 화면 하단에서 일정한 위치와 크기로 사용할 수 있게 구성한다. 시스템 키보드가 열려도 입력칸과 버튼의 크기는 바꾸지 않는다.
4. 입력 본문과 하단 동작 영역을 구분해 스크롤 책임을 명확히 한다. 현재의 작은 창 전체를 스크롤하는 사용 방식은 복원 대상으로 본다.
5. 내용 이력은 내용칸과 연결된 하나의 목록으로 표시한다. Android에서는 키보드·클리핑·터치 선택 검증을 거쳐 배치하고, 포털 사용 여부와 사용자에게 보이는 동작을 구분한다.
6. 최근 적용한 민트 배경·젤리 로고·현재 테마는 유지한다. 사용 방식 복원 때문에 앱 전체를 예전 웹 색상으로 되돌리지 않는다.

웹 CSS는 휴대폰에서 `dvh`에 따라 입력 높이·여백·글자 크기를 함께 바꾼다. 이 값을 그대로 복사하면 Android 키보드 전환 시 크기가 다시 달라질 수 있다. 웹앱의 조작 구조를 복원하면서 IME 높이 변화가 입력 크기를 바꾸지 않도록 구현해야 한다.
