# 공유 장부 생성 테스트

2026-10-14 · APK 0.3.0-test / versionCode 5 · HTTPS 테스트 서버에만 배포.

2026-10-15 최신 설치 파일: `Memoney-ledger-ui-0.3.1.apk` / versionCode 6. 장부 톱니 제거·드롭다운 생성/관리·호스트/게스트 표시를 APK의 포함 화면에도 반영했다. 기존 앱 위에 업데이트 설치한다. 서버 반영만으로 이미 실행 중인 휴대폰 WebView의 화면까지 즉시 교체된다고 보장하지 않는다. 이전 APK의 포함 화면에 톱니가 남아 있었지만 서버 연결은 같은 HTTPS 주소였으므로, 이것만으로 휴대폰 증상의 원인이 확정됐다고 보고하지 않는다. 새 APK의 서명과 포함 화면, 에뮬레이터 업데이트 설치를 확인했다.

## 사용자 흐름

Google 로그인 → 설정의 장부 드롭다운 → 공유 장부 만들기 → 이름 입력 → 개인 장부 복사하기 또는 빈 장부로 시작하기.

2026-10-15 UI 정리: 장부 옆 톱니와 생성·관리 화면의 중복된 개인 장부 선택 버튼을 제거했다. 공유 장부가 없으면 드롭다운에 `공유 장부 만들기`, 있으면 이름과 `호스트/게스트`를 표시하고 `공유 장부 관리` 항목으로 이름 변경·초대를 연다. 생성 화면 제목도 기능 이름을 사용한다. 뒤로가기는 진입한 로컬/클라우드 화면으로 돌아간다. 생성 완료 시 새 장부를 클라우드 선택으로 지정하므로 클라우드 화면으로 돌아가면 새 공유 장부가 열린다.

복사 준비 중에는 버튼에 준비 상태를 표시한다. 복사가 시작되면 실제 처리 건수·전체 건수와 진행률을 표시하고 40개 행씩 처리한다. 복사 원본은 서버에서 한 시점의 스냅샷으로 고정한다. 연결 실패 시 진행 상태를 남기고 `이어서 진행`을 제공한다. 앱을 닫고 다시 장부 관리에 들어가도 서버에 보관한 같은 작업을 재개한다. 앱이 닫힌 동안 복사가 백그라운드에서 계속된다고 보장하지 않는다.

복사 완료 후 목록에서 공유 장부를 열고 Google 계정을 지정해 초대한다. 받은 초대는 기존처럼 첫 장부 화면의 팝업에서 명시적으로 수락한다. 이름은 생성 시 필수이며 서버에서 앞뒤 공백 제거 후 1~30 Unicode 코드 포인트로 검증한다. 이름 변경은 소유자에게만 허용하고 UUID는 유지한다.

계정당 소유 공유 장부는 1개다. 복사 중인 장부도 한도에 포함한다. DB의 소유자 UNIQUE 제약과 생성 operation ID/요청 해시가 동시 요청과 재시도를 처리한다. 다른 사람의 초대를 수락해 참여하는 장부는 생성 한도와 별개다. 이전 공유 테스트 메타데이터는 생성 한도에 포함하지 않는다.

## 저장 경로와 복사 범위

- 개인 금융 DB: `memoney-android-test-personal`. 공유 금융 DB: 새로 만든 `memoney-android-test-shared`. 인증·멤버십·생성 작업 메타데이터는 기존 테스트 인증 DB를 사용한다.
- 기존 웹앱 금융 DB와 웹 배포는 유지한다. 공유 생성·복사·수정은 웹 DB로 전달하지 않는다.
- 이번 격리 테스트는 공유 UUID에서 도출한 서버 전용 테이블 이름(`s_<uuid>_<table>`)으로 공유 장부마다 모든 금융 테이블을 분리한다. 기존 금융 핸들러의 revision·operation·증분 API를 동일하게 사용한다. SQL과 테이블 식별자는 서버 코드에서만 만들고 데이터 값은 bind한다. 정식 웹 이관 시의 장부 테이블 구조와 운영 규모 검증은 별도 단계다.
- 거래·자산·카테고리·계획·정기 규칙과 시간·정기 제외 ID·카드 결제·예산 및 금융 설정·참조를 복사한다. 장부별 테이블로 분리하므로 원본 행 ID를 그대로 보존할 수 있다.
- 개인 테마·operation 결과·sync_changes 이력·세션·초대·멤버십은 복사하지 않는다. 새 장부 cursor는 0부터 시작한다. 개인 장부와 공유 장부는 복사 이후 독립적으로 변경한다.
- 이 기기에 개인 장부의 저장 대기 기록이 있으면 먼저 개인 장부에서 저장을 완료하도록 안내한다. 로컬 장부를 로그인만으로 업로드하지 않는다. 이번 생성의 `개인 장부 복사하기`는 연결된 개인 클라우드 장부를 원본으로 한다. 로컬 원본 복사는 별도 후속 범위다.
- 복사 중에는 데이터 조회·수정·초대가 차단된다. 공유 DB의 복사가 완료된 뒤 인증 DB에서 owner membership과 ready 상태를 함께 공개한다. 중간 실패 시 같은 작업으로 이어서 완료한다. 완료된 작업에 대한 늦은 복사 요청은 이후 수정된 데이터를 다시 생성하지 않는다.
- 금융 요청·캐시·로컬 가져오기 모두 선택한 장부 ID를 사용한다. 다른 계정의 이전 선택이나 철회된 장부 선택은 서버에서 거부하고 접근 가능한 기본 장부로 다시 확인한다.

## 배포·검증

`scripts/shared-creation-auth-schema.sql`은 테스트 인증 DB에, `scripts/shared-creation-finance-schema.sql`은 새 공유 테스트 DB에 한 번만 적용했다. 기존 개인 금융 DB와 웹 DB에는 이 초기화 SQL을 실행하지 않는다. 이후 배포에서 다시 실행하지 않는다.

`scripts/generate-shared-schema.mjs`가 검사된 금융 schema로 서버의 공유 장부 생성 schema를 만든다. 기반 schema를 변경하면 이 스크립트를 실행한 뒤 회귀 검사를 수행한다.

자동 검증: `npm run check:auth`, `node scripts/check-shared-creation-ui.mjs`. 실제 SQLite에서 전체 복사 행·컬럼·참조, 시간 지정 정기 규칙, 재개, 동시 생성 한도, 서로 다른 장부의 같은 기록 ID 분리, 이름 변경, 초대 수락·권한을 검사한다. 브라우저의 격리 API 모의 환경에서는 40% 중단 → 재시작 → 이어서 진행 → 100% 완료, 320/411/768 화면 폭, 생성 후 목록을 확인한다.

설치한 에뮬레이터의 실제 Google 세션으로 서버의 장부 목록과 생성 화면을 확인한다. 실제 사용자 소유 한도는 비워 두므로 사용자가 이름과 시작 방식을 선택해 처음 생성할 수 있다. 실제 두 Google 계정 간 참여는 사용자의 후속 테스트이며 자동 검사를 실제 상대방 로그인 성공으로 보고하지 않는다.

완료 시 검증 결과: 자동 검사 47건 통과, 진행률·재개 UI 및 3가지 화면 폭 검사 통과, 기존 받은 초대 팝업·로그인 전환·계정 로그아웃 회귀 검사 통과. 최신 APK 서명을 확인하고 에뮬레이터에 업데이트 설치했다. 실제 서버의 목록 요청은 200이며 사용자 생성 한도는 비어 있다. 원본 웹 DB·개인 금융 DB에 시험 생성이나 수정 요청을 보내지 않았다.
