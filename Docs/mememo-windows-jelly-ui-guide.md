# MEMEMO Windows 앱 젤리 UI 적용 지침

2026-10-26. 메머니(Memoney)의 현재 메메모 계열 UI·애니메이션 구현을 MEMEMO Windows 앱에 전달하기 위한 문서다. 조사 기준은 이 브랜치의 실제 소스이며, Windows 앱의 기술 스택이나 현재 코드를 확인한 문서는 아니다. 아래 플랫폼별 항목은 이식 설계 지침으로 구분한다. Windows 적용·검증·배포는 아직 하지 않았다.

색상 기준은 [MEMEMO 브랜드 색상 규격](mememo-brand-colors.md)을 따른다. 대표 민트 `#ABE8C3`, 강조 딥그린 `#36785B`, 브랜드 잉크 `#233E31`를 사용하며 젤리 표면색과 라이트/다크 역할색을 분리한다.

## 1. 재현할 인상과 구조

- 민트·초록 표면, 얇은 잉크 테두리, 작은 그림자, 상단 광택으로 말랑한 재질을 표현한다.
- 누를 때 세로로 더 많이 눌리고, 뗄 때 한 번 탄성 있게 원래 형태로 돌아온다.
- 실제 버튼·메뉴의 클릭 영역과 레이아웃은 고정한다. 내부 표면·아이콘만 변형한다.
- 탭 전환은 글자와 버튼을 이동시키지 않고 선택 배경 하나가 다음 항목 아래로 움직인다.
- 입력할 때마다 모달이 흔들리지 않는다. 열릴 때만 한 번 등장한다.

부드러운 재질은 공통으로 유지하지만 모든 버튼에 같은 강도로 탄성을 넣지 않는다. 메뉴 선택은 약하게, 주요 추가 버튼은 더 분명하게, 입력 필드는 고정한다.

## 3. 표면 재질

선택 배경은 `jelly.top → jelly.bottom`의 145도 그라데이션을 기본으로 사용한다. 그 위에 다음 광택을 합성한다.

```css
/* 토큰 이름은 Windows 앱에 옮길 때의 독립 이름 예시다. */
.mememo-jelly-surface {
  border: 1px solid var(--mememo-jelly-edge);
  border-radius: 6px;
  background:
    linear-gradient(180deg, rgb(255 255 255 / 24%), transparent 48%, rgb(0 0 0 / 3%)),
    linear-gradient(145deg, var(--mememo-jelly-top), var(--mememo-jelly-bottom));
  box-shadow:
    inset 0 1px 0 rgb(255 255 255 / 65%),
    inset 0 -1px 1px rgb(0 0 0 / 9%);
}
```

현재 선택 배경에는 추가로 primary RGB 기반 15% 농도의 `0 1px 2px` 외부 그림자가 있다. 상단 광택 보조 레이어는 좌우 15% 안쪽, 상단 2px, 높이 25%이며 흰색 50%에서 투명으로 내려간다. 배경과 광택은 마우스 입력을 가로채지 않는다.

메뉴·추가 버튼은 좌상단 `(28%, 5%)`의 흰색 55% 방사형 광택을 사용하고, 65% 지점에서 투명해진다. 그림자는 상단 안쪽 흰색 65% 1px, 하단 안쪽 검정 10% 2px다. 거대한 외부 그림자나 상시 반짝이는 애니메이션은 추가하지 않는다.

## 4. 움직임 수치

px는 현재 웹의 CSS 논리 픽셀이다. Windows 이식에서는 같은 값을 먼저 논리 단위로 다루고 DPI 검수를 거친다. 애니메이션 곡선은 CSS cubic-bezier 기준이며 스프링 물리 파라미터를 측정한 값은 아니다.

| 대상 | 누르는 동안 | 복원/이동 |
| --- | --- | --- |
| 일반 내비게이션 표면 | Y +2px, scale X .94 / Y .88, 85ms ease-out | 280ms `(.18,.9,.32,1.45)` |
| 일반 내비게이션 글자 | Y +1px, scale .90, 85ms ease-out | 280ms 같은 곡선 |
| 내비게이션 추가 버튼 표면 | Y +3px, scale .90 / .82 | 280ms 같은 곡선 |
| 추가 버튼 아이콘 | Y +2px, scale .84 | 280ms 같은 곡선 |
| 별도 데스크톱 등록 버튼 표면 | Y +2px, scale .96 / .88, 85ms | 280ms 같은 곡선 |
| 별도 데스크톱 등록 버튼 내용 | Y +1px, scale .93, 85ms | 280ms 같은 곡선 |
| 선택 토글 배경 | 위치 transform 240ms `(.2,.85,.3,1.08)` | 폭 220ms `(.2,.8,.2,1)` |
| 키패드 광택층 | Y +1px, scale .96 / .87, opacity .5, 55ms ease-out | 240ms `(.2,.85,.25,1.5)` |
| 키패드 내용 | Y +2px, scale .92 / .88, 55ms ease-out | 240ms 같은 곡선 |

내비게이션 선택 표면 opacity는 평상시 100ms ease, 눌림 진입은 60ms ease다. 선택 메뉴의 글자·테두리 색 전환은 160ms ease다. hover 때문에 브랜드색을 일괄 어둡게 만드는 효과를 추가하지 않는다.

### 팝업·드롭다운 키프레임

| 대상 | 0% | 중간 | 완료 |
| --- | --- | --- | --- |
| 선택 팝업, 360ms | Y +70px, scale .98/.94, opacity 0 | 58%: Y -5px, 1.006/1.018, opacity 1; 80%: Y +2px, .998/.992 | 100%: 변형 없음, opacity 1 |
| 설정 드롭다운, 360ms | Y -8px, scale 1/.86, opacity 0 | 58%: Y +2px, 1.006/1.035, opacity 1; 80%: Y -1px, .998/.988 | 100%: 변형 없음, opacity 1 |
| 등록 모달, 280ms ease-out | Y +10px, scale .985/.97 | 65%: Y -1px, 1.002/1.004 | 100%: 변형 없음 |
| 금액 표시, 190ms ease-out | Y +3px, scale .97/.92, opacity .65 | 60%: Y -1px, 1.015/1.04, opacity 1 | 100%: 변형 없음, opacity 1 |

선택 팝업과 드롭다운의 CSS animation은 별도 timing-function을 지정하지 않아 기본 ease를 사용한다. 팝업 원점은 모바일 하단 중앙, 데스크톱(현재 769px 이상)은 중앙이다. 드롭다운 원점은 상단 중앙이다. 펼침 화살표는 240ms 토글 곡선으로 180도 회전한다. 드롭다운을 누르는 입력 필드 자체는 함께 축소하지 않는다.

## 5. 선택 토글 구현 계약

`JellyToggle`은 환경·카테고리·자산관리·정기기록·데이터와 장부·계획·차트 등의 선택에 재사용한다.

1. 선택 상태가 바뀌면 **기능 상태는 즉시 변경**한다. 애니메이션 종료를 기다려 실행하지 않는다.
2. 선택 버튼의 실제 bounds를 측정한다. 항목 수로 전체 폭을 나눈 값만 사용하지 않는다. 글자 줄바꿈·버튼 간격·테두리·스크롤을 반영한다.
3. 컨테이너 기준 위치는 `button.left - container.left - container.clientLeft + container.scrollLeft`, 세로도 같은 방식으로 계산한다.
4. 배경 표시 하나를 absolute 레이어에 두고 위치와 폭을 보간한다. 버튼과 글자는 그 위에 고정한다. 배경은 hit test에서 제외한다.
5. 최초 표시에는 이동 애니메이션을 넣지 않는다. 이후 선택 변경만 이동한다.
6. 창·컨테이너·각 버튼의 크기 변경과 폰트 준비 완료 때 다시 측정한다. 크기 재측정 때는 애니메이션을 끄고 즉시 정렬한다.
7. 빠르게 연속 클릭하면 마지막 선택으로 수렴해야 한다. 이전 애니메이션의 완료 콜백이 새 선택을 되돌리지 않아야 한다.

기본 테마의 thumb 모서리는 6px, 각진 테마1은 0이다. 같은 동작 규칙을 사용하고 모서리만 테마 토큰으로 분기한다. 메머니의 현재 측정 로직과 CSS를 출발점으로 삼되, Windows 컨트롤의 레이아웃 이벤트·입력 체계에 맞게 구현한다.

## 6. 버튼 레이어와 입력

권장 구조는 `고정된 실제 버튼 → 변형되는 표면 + 변형되는 내용`이다. Windows 네이티브 UI도 이 레이어 구성을 유지한다.

- 누름 영역의 Width/Height, Margin, Padding을 프레임마다 바꾸지 않는다. 레이아웃 계산이 아닌 렌더 변형으로 표현한다.
- 아이콘의 기본 중심은 버튼 중심에 맞춘다. 누름 때만 정해진 이동을 적용한다. 기본 위치 보정을 누름 애니메이션과 같은 transform 속성에 덮어쓰지 않는다.
- 텍스트 `‹`, `×`는 글꼴에 따른 중심 차이가 있으므로 공통 벡터 아이콘을 사용한다. 현재 헤더는 44×44 버튼 안의 24×24 SVG이고, 도형 경로의 bounds 중심까지 검사한다.
- 마우스 누름 후 버튼 밖으로 이동·취소·창 비활성화·pointer capture 해제가 발생하면 눌림 상태를 정리한다. 파괴적 작업은 임의의 pointer-down에서 실행하지 않는다.
- 키보드 Space/Enter와 마우스 클릭이 같은 동작 경로를 사용하게 한다. 포커스 링은 광택과 별도로 유지한다.
- 비활성 버튼에는 눌림 반응과 명령 실행을 허용하지 않는다. 장부 초기화 등은 상태 조회 전부터 버튼을 표시하되 검증 완료 전 비활성 상태로 둔다.

## 7. MEMEMO Windows 적용 방법

기술 스택을 먼저 확인한 뒤 아래 경로 중 하나를 선택한다. 이식 시의 권장 설계이며 실제 MEMEMO 구현 완료를 뜻하지 않는다.

| UI 구성 | 적용 방향 |
| --- | --- |
| Electron/Tauri/WebView 기반 | 젤리 토큰·공통 CSS와 선택 배경 측정 구조를 재사용한다. React라면 `JellyToggle`부터 분리할 수 있다. 앱별 DOM 선택자와 전역 스타일은 가져오지 않는다. |
| WinUI/Windows App SDK | 컨트롤 템플릿의 배경과 내용을 분리하고, 렌더/Composition 변형에 위 시간·스케일을 대응시킨다. API와 easing 지원은 프로젝트 버전에서 확인한다. |
| WPF | ControlTemplate의 고정 버튼 안에 표면·내용 레이어를 두고 RenderTransform/Storyboard로 대응시킨다. LayoutTransform으로 버튼 영역을 흔들지 않는다. |

네이티브 프레임워크가 위 곡선의 1 초과 제어점을 그대로 지원하지 않으면 값을 조용히 1로 잘라 탄성을 없애지 않는다. 지원되는 키프레임으로 작은 오버슈트와 복원을 재현하고 영상으로 비교한다. `1.45` 같은 cubic-bezier 제어점은 최종 scale을 1.45배로 키우라는 의미가 아니다.

## 8. 화면 크기·DPI·성능·접근성

- 창을 좁히거나 100/125/150/200% DPI로 바꾼 뒤 선택 배경이 버튼에 정확히 맞는지 확인한다. 물리 픽셀 좌표와 CSS px/DIP를 혼합하지 않는다. 이동 도중 값은 일찍 정수 반올림하지 않는다.
- 젤리 표면의 작은 확장을 허용할 여백과 clipping 정책을 정한다. 광택을 둥글게 자르는 레이어가 반동 전체를 잘라내지 않도록 한다.
- 입력 모달은 첫 진입에서만 애니메이션을 실행한다. 타이핑·검증 메시지·상태 갱신 때 재마운트하거나 전체 등장 애니메이션을 재시작하지 않는다.
- 헤더는 고정하고 폼에 헤더를 제외한 실제 가용 높이를 준다. 높이가 낮으면 여백을 줄이며 내용이 실제로 넘을 때 스크롤한다. 키보드 등장만으로 필드 높이를 계속 재계산해 흔들지 않는다.
- transform/opacity 중심으로 처리한다. 매 프레임 큰 blur·그림자·전체 창 재측정을 애니메이션하지 않는다. 유휴 상태에서 반복 애니메이션을 돌리지 않는다.
- Windows의 동작 줄이기/애니메이션 비활성 설정을 공통 정책에 연결한다. 웹 UI는 `prefers-reduced-motion`에서 등장·탄성·이동을 끄고 최종 선택 상태를 즉시 표시한다.
- 고대비·키보드 전용 사용에서도 포커스와 선택을 구분한다. 색상 대비는 [브랜드 문서](mememo-brand-colors.md)의 규칙으로 검증한다.

## 9. 적용 순서와 검수

1. 브랜드/표면/동작 토큰을 공통 리소스로 만든다.
2. 설정 등 하나의 세그먼트 메뉴에 선택 배경을 적용한다.
3. 일반 메뉴와 주요 추가 버튼의 내부 눌림을 적용한다.
4. 드롭다운·팝업 등장과 모달 1회 등장에 적용한다.
5. 라이트/다크·창 크기·DPI·마우스/키보드·취소·빠른 반복 입력·동작 줄이기에서 확인한 뒤 다른 화면으로 확장한다.

검수 기준은 버튼 영역 고정, 도형/글자 중심, 선택 배경 정렬, 정상/눌림/복원 일관성, 중복 실행 없음, 입력 중 모달 재등장 없음이다. 저장·동기화·로그인 동작은 스타일을 옮기기 위해 변경하지 않는다.

현재 메머니의 참고 검사:

- [check-settings-controls.mjs](../scripts/check-settings-controls.mjs): 12개 화면/테마 조합의 선택 배경 정렬·광택·동작 줄이기와 지연 초기화 버튼 상태.
- [check-page-action-centers.mjs](../scripts/check-page-action-centers.mjs): 실제 SVG 경로 중심과 44px 버튼 중심의 0.1px 이내 일치.
