# 장부 자동 재연결

앱 복귀 시 네트워크 오류나 일시적인 서버 오류를 로그인 만료로 처리하지 않는다. 이미 열린 장부와 작성 중인 입력창을 유지하며 연결을 다시 확인한다.

- 첫 진입에서 연결을 확인하는 동안 사용자가 제공한 `/images/met-sleep.gif`를 표시한다. 일시 오류가 발생해도 안내 문구 없이 자동으로 재시도한다.
- 장부 화면의 초기 로딩까지 완료되면 `/images/met-meow.gif`를 표시하고, 이미지가 준비된 뒤 0.7초 후 메인 화면을 공개한다. 이때 장부는 뒤에서 준비하며 추가 로딩 화면이 끼어들지 않는다. 백그라운드에서는 완료 표시 시간을 세지 않고 복귀 시 다시 0.7초를 확보한다.
- meow 이미지의 디코딩이 끝날 때까지 sleep을 유지하고, 준비되면 두 이미지의 표시를 한 번에 교체한다. 전환 효과로 겹치거나 이미지 로딩 중 빈 화면이 생기지 않도록 한다. meow 로딩 실패 시에는 sleep을 유지한 채 메인 화면으로 진입한다.
- 재시도 간격은 1초부터 최대 15초까지 늘어난다. 화면 복귀와 네트워크 복구 시 즉시 재시도하며 요청이 겹치지 않게 한다.
- 서버가 401·403으로 접근 거부를 확인한 경우에는 장부 접근을 잠그고 로그인 화면으로 이동한다. 세션 유효기간과 인증 정책은 유지한다.
- 재검증에서 계정·장부·역할이 바뀌면 저장 공간을 다시 초기화하도록 페이지를 새로 연다.
- 로그아웃 실패의 재시도는 로그아웃 요청을 다시 수행한다.
- 로그인 후 원격 응답은 정상인데 로딩이 반복될 경우 캐시 용량도 확인한다. 2026-10-21 에뮬레이터에서는 기존 백업 28개가 쌓인 상태에서 `QuotaExceededError`가 발생했다. 유효한 원격 데이터를 받은 뒤의 복구용 캐시 저장 용량 오류는 진입 실패로 처리하지 않는다. App의 기존 D1 초기 조회가 끝난 뒤 화면을 공개하며, 보류 중인 수정이 있으면 기존대로 사전 캐시 교체를 건너뛴다.
- 사전 캐시 백업은 고정된 `pre-d1-backup` 한 슬롯을 갱신하고, 매번 타임스탬프 이름으로 복사본을 추가하지 않는다. 이미 존재하는 백업과 저장 데이터는 삭제하지 않는다.
- 수정 배포 후 같은 에뮬레이터의 저장 데이터를 유지한 채 WebView를 다시 열어, `/wallet` 메인 화면 진입과 로딩 종료를 확인했다. Google 계정 선택 UI의 처리 시간 전체를 측정한 것은 아니며, 확인된 장애는 인증 후 캐시 저장 단계의 반복 실패다.

저장 키, D1 우선 정책, 보류 중인 변경 및 금융 데이터 저장 로직은 변경하지 않는다. APK에 포함된 네이티브 네트워크 오류 화면은 별도이며 이번 변경 대상에 포함되지 않는다.

## 검증

- `npm run check:auth`: 48개 통과. HTTP 상태에 따른 접근 거부와 일시 오류의 구분을 포함한다.
- `npm run build`: 통과.
- `node scripts/check-wallet-reconnect.mjs`: 로컬 브라우저 시나리오 10개. 백업·캐시의 용량 초과 시 진입과 기존 백업 보존, meow 로딩 지연 중 빈 프레임·겹침 여부, sleep → meow → 메인 화면의 순서·완료 표시 시간, 시작 시 네트워크·서버 오류 복구, 데이터 로딩 재시도, 복귀 시 미저장 입력 보존, 중복 요청 방지, 실제 세션 만료, 로그아웃 재시도를 확인한다. 금융 데이터 쓰기 요청은 0회다.

브라우저 검증은 로컬 응답으로 실행한다. 장시간 백그라운드 후 실제 Android 기기의 복귀 동작은 별도 실기기 확인이 필요하다.
