# Memoney 연 구독·무료 이용 정책

2026-10-24 · 사용자 확정 방향. 출시 준비와 함께 단계별 구현·검증·커밋한다.

## 상품과 적용 범위

- 앱 설치는 무료이며 프리미엄은 자동 갱신 연 구독으로 제공한다. 일회성 영구 구매로 구현하지 않는다. 연간 가격은 아직 확정하지 않았다.
- 구현용 상품 식별자는 `memoney_premium`, 기본 요금제는 `annual`, 결제 주기는 `P1Y`다. 이는 코드의 예정 식별자이며 Play Console에 상품을 등록·활성화했다는 의미가 아니다. 실제 가격과 통화는 이후 Play 상품 정보를 사용한다.
- 무료 기본값은 장부당 자산 10개, 작성자 계정당 하루 입력 10건, 광고 보상 1회당 추가 입력 10건이다. 실제 제한 활성화 전에 UI와 집계 경계를 검증한다.
- 공유 장부의 자산 한도는 **장부 호스트의 구독**으로 결정한다. 호스트가 구독 중이면 그 장부의 게스트도 확장된 자산을 함께 사용한다. 게스트 본인만 구독했다고 호스트 장부의 자산 한도가 늘지는 않는다.
- 광고 제거·일일 입력 한도 해제는 **기록을 작성하는 사람 본인의 구독**으로 결정한다. 유료 호스트 장부에 참여한 미결제 게스트에게도 무료 입력·광고 정책이 적용된다. 이 정책은 기존 owner/editor/viewer 권한을 추가하거나 대체하지 않는다.
- 개인 장부는 소유자와 작성자가 같으므로 본인의 구독을 두 항목에 모두 적용한다.

## 기존 기록 보호

구독 만료나 결제 보류로 혜택이 끝나도 기존 거래·자산을 지우지 않는다. 보유 자산이 이미 10개를 넘으면 새 자산 추가만 제한하고 기존 기록의 조회·수정·내보내기를 구독 때문에 막지 않는다. 기존 장부 접근 권한 검사는 그대로 적용한다.

장부 저장 전에 갑자기 광고를 표시하지 않는다. 저장 완료 후 다음 등록에서 광고를 통한 추가 이용을 선택할 수 있도록 한다. 광고 로딩 실패나 취소가 작성 중 내용의 유실로 이어져서는 안 된다.

## 구현된 1단계

- `server/billing/annual.ts`: Google Android Publisher의 `subscriptionsv2.get` 응답을 서버에서 확인한다. 패키지·상품·연 요금제·난독화된 메머니 계정 식별자가 맞는 구매만 정상화한다. 클라이언트의 `premium=true`나 이메일로 결제 소유자를 결정하지 않는다.
- 구독 취소는 Google이 반환한 만료 시각까지 혜택을 유지한다. 결제 유예기간에도 혜택을 유지하고, 결제 보류·일시중지·만료·구매 대기는 혜택을 부여하지 않는다. 결제 대기와 승인 완료를 혼동하지 않는다.
- `server/billing/policy.ts`: 장부 호스트의 자산 권한과 작성자 본인의 광고/입력 권한을 따로 계산한다. 보상 횟수는 이후 서버 검증된 광고 기록만 전달한다.
- `server/billing/store.ts`: 서버 검증기가 같은 프로세스에서 만든 구매 결과만 인증 DB에 기록한다. 구매 토큰은 해시로 식별하고 원문 토큰·결제 자격증명은 저장 결과에 포함하지 않는다. 다른 계정으로 구매를 재연결하지 않으며 늦은 검증 결과가 더 최신 상태를 덮어쓰지 않는다.
- 구매별 행을 보존하므로 이전 토큰의 만료가 별도의 정상 구독을 해제하지 않는다. 계정 권한은 여러 구매 중 유효한 연 구독에서 계산한다.
- 인증 DB용 추가 스키마는 `scripts/billing-auth-schema.sql`이다. 금융 DB의 초기화·장부 복구·백업과 별개이며 운영 DB에는 적용하지 않았다.
- `npm run check:billing` 13건으로 호스트/게스트 조합, 취소·유예·만료 경계, 보상 횟수, 계정/상품 불일치, Google 장애, 구매 소유권·오래된 상태 경합을 격리 검증했다.

현재 코드는 결제·제한의 서버 기반이다. 앱 결제 화면, 실제 결제/광고 SDK, 공개 구매 API, 운영 제한을 활성화한 상태가 아니다. 기존 사용자의 등록 흐름을 변경하지 않았다.

## 다음 구현

1. Play Billing 네이티브 연결과 연 상품 조회·구매·복원. 구매 시작에 `billingAccountId(userId)`를 `obfuscatedAccountId`로 전달하고 앱 계정 변경을 검사한다. 메머니 로그인 계정과 Play 구매 계정이 같다고 가정하지 않는다.
2. 서버 서비스 계정 인증, 구매 검증 API, 구매 승인(acknowledgement), RTDN 수신·Google 재조회. RTDN 알림 종류만으로 혜택을 부여하거나 해제하지 않는다. 서비스 계정 비밀 키를 앱·Git·채팅에 넣지 않는다.
3. 인증 DB 스키마 검토·적용과 계정별 권한 조회. 운영 적용은 실제 결제 상품·서비스 계정·환불/복원 검증 뒤 진행한다. 서버 상태를 확인하지 못한 것을 신규 결제 성공으로 처리하지 않는다.
4. AdMob 보상형 광고와 서명된 서버 보상 검증. 광고 이벤트 ID의 재전송으로 이용권이 중복 발급되지 않게 한다. 광고 테스트에는 테스트 광고 단위만 사용한다.
5. 거래 저장과 이용량 집계 연동. 성공한 고유 작업만 차감하고, 저장 실패·응답 유실·재시도·여러 기기 동시 등록을 기존 operation ID로 대조한다. 여러 물리 DB의 개인/공유 장부를 사용하는 계정의 이용량을 단순 조회 후 증가 방식으로 구현하지 않는다. 중간 실패의 예약/확정/재조정까지 검증한 뒤 활성화한다.
6. 기기 로컬 모드·오프라인 동작, 날짜/시간대 경계, 정기 자동 발생·할부·가져오기·백업 복원의 집계 범위를 확정한다. 제한 때문에 정상 정기 거래가 누락되거나 복원 데이터가 잘리지 않도록 한다.
7. 구매·갱신·유예·환불·만료·재로그인·앱/웹 권한 동기화와 공유 장부 호스트 변경을 분리된 시험 계정/장부로 확인한다.
