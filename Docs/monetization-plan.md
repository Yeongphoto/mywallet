# Memoney 연 구독·무료 이용 정책

2026-10-24 · 사용자 확정 방향. 출시 준비와 함께 단계별 구현·검증·커밋한다.

## 상품과 적용 범위

- 앱 설치는 무료이며 프리미엄은 자동 갱신 연 구독으로 제공한다. 사용자가 연 판매 가격을 **2,000원**으로 확정했다. 등록 기준은 `config/billing-catalog.json`에 기록하며 앱의 실제 가격 표시는 Google Play 상품 조회를 사용한다.
- 구현용 상품 식별자는 `memoney_premium`, 기본 요금제는 `annual`, 결제 주기는 `P1Y`다. 이는 코드의 예정 식별자이며 Play Console에 상품을 등록·활성화했다는 의미가 아니다. 실제 가격과 통화는 이후 Play 상품 정보를 사용한다.
- 무료 기본값은 장부당 자산 10개, 작성자 계정당 하루 입력 10건, 광고 보상 1회당 추가 입력 10건이다. 실제 제한 활성화 전에 UI와 집계 경계를 검증한다.
- 공유 장부의 자산 한도는 **장부 호스트의 구독**으로 결정한다. 호스트가 구독 중이면 그 장부의 게스트도 확장된 자산을 함께 사용한다. 게스트 본인만 구독했다고 호스트 장부의 자산 한도가 늘지는 않는다.
- 광고 제거·일일 입력 한도 해제는 **기록을 작성하는 사람 본인의 구독**으로 결정한다. 유료 호스트 장부에 참여한 미결제 게스트에게도 무료 입력·광고 정책이 적용된다. 이 정책은 기존 owner/editor/viewer 권한을 추가하거나 대체하지 않는다.
- 개인 장부는 소유자와 작성자가 같으므로 본인의 구독을 두 항목에 모두 적용한다.

## 기존 기록 보호

구독 만료나 결제 보류로 혜택이 끝나도 기존 거래·자산을 지우지 않는다. 보유 자산이 이미 10개를 넘으면 새 자산 추가만 제한하고 기존 기록의 조회·수정·내보내기를 구독 때문에 막지 않는다. 기존 장부 접근 권한 검사는 그대로 적용한다.

장부 저장 전에 갑자기 광고를 표시하지 않는다. 저장 완료 후 다음 등록에서 광고를 통한 추가 이용을 선택할 수 있도록 한다. 광고 로딩 실패나 취소가 작성 중 내용의 유실로 이어져서는 안 된다.

## 구현된 1단계

- `server/billing/annual.ts`: Google Android Publisher의 `subscriptionsv2.get` 응답을 서버에서 확인한다. 패키지·상품·연 요금제·난독화된 메머니 계정 식별자가 맞는 구매만 정상화한다. 클라이언트의 `premium=true`나 이메일로 결제 소유자를 결정하지 않는다.
- 구독 취소는 Google이 반환한 만료 시각까지 혜택을 유지한다. 결제 유예기간에도 혜택을 유지하고, 결제 보류·일시중지·만료·구매 대기는 혜택을 부여하지 않는다. 결제 대기와 승인 완료를 혼동하지 않는다.
- `server/billing/policy.ts`: 장부 호스트의 자산 권한과 작성자 본인의 광고/입력 권한을 따로 계산한다. 보상 횟수는 이후 서버 검증된 광고 기록만 전달한다.
- `server/billing/store.ts`: 서버 검증기가 같은 프로세스에서 만든 구매 결과만 인증 DB에 기록한다. 구매 토큰은 해시로 식별하고 원문 토큰·결제 자격증명은 저장 결과에 포함하지 않는다. 다른 계정으로 구매를 재연결하지 않으며 늦은 검증 결과가 더 최신 상태를 덮어쓰지 않는다.
- 구매별 행을 보존하므로 이전 토큰의 만료가 별도의 정상 구독을 해제하지 않는다. 계정 권한은 여러 구매 중 유효한 연 구독에서 계산한다.
- 인증 DB용 추가 스키마는 `scripts/billing-auth-schema.sql`이다. 금융 DB의 초기화·장부 복구·백업과 별개이며 운영 DB에는 적용하지 않았다.
- `npm run check:billing` 13건으로 호스트/게스트 조합, 취소·유예·만료 경계, 보상 횟수, 계정/상품 불일치, Google 장애, 구매 소유권·오래된 상태 경합을 격리 검증했다.

현재 코드는 결제·제한의 서버 기반이다. 앱 결제 화면과 실제 결제/광고 SDK, 운영 제한을 활성화한 상태가 아니다. 기존 사용자의 등록 흐름을 변경하지 않았다.

## Android 결제 연결과 설정 화면

- Play Billing Library 9.1.0 기반 `MemoneyBillingPlugin`을 등록했다. 정식 `com.memoney.app`의 신뢰된 번들 화면에서 명시적으로 켠 경우만 사용한다. 검증 패키지와 기존 개발 앱에서는 구매를 시작하지 않는다.
- 상품 조회·구매·복원·구독 관리 메서드를 구현했다. 상품과 연 요금제, `P1Y` 자동 갱신 가격만 선택하며 매 구매 때 ProductDetails/offer token을 다시 조회한다. 앱에서 가격을 고정해 결제하지 않는다. 결제 승인은 서버에서 처리한다.
- 메머니 계정의 난독화된 식별자를 구매에 연결한다. 복원에서도 해당 계정의 구매만 반환하고, 결제 창 전후 계정이 달라지면 서버 연결을 중단한다. 구매 토큰을 localStorage에 보관하지 않는다.
- 설정의 연 구독 시작·구매 복원·구독 관리 화면을 연결했다. 실제 서버와 네이티브 양쪽에서 결제가 활성화된 경우에만 노출한다. 기존 프리미엄 사용자에게 중복 구매를 띄우지 않고, 결제 대기·취소·상품 조회 실패·구매 승인 지연을 구분한다.
- `BILLING_ENABLED`와 정식 프로필의 `MemoneyBilling.enabled`는 계속 비활성이다. 실제 상품·서명·서비스 계정·RTDN과 테스트 구매를 확인하기 전에는 운영 결제를 켜지 않는다.
- 모의 화면은 `/scripts/ui-fixtures/billing.html`이며 production 빌드에는 포함하지 않는다. `npm run check:billing-ui`로 라이트/다크와 320·411·768px, 모의 구매·복원·관리·취소를 확인한다. 미리보기의 연 2,000원은 등록 예정 값이며 실제 청구가 없다.
- `npm run check:billing` 29건, 구성 24건, 네이티브 전송 9건, 웹 빌드와 정식 준비 프로젝트의 실제 Java 컴파일이 통과했다. APK/AAB 생성 차단은 유지하며 의존 라이브러리 내부 JAR 컴파일만 허용하도록 가드의 프로젝트 범위를 명확히 했다.
- Billing SDK가 포함된 최신 검증 APK를 삼성 실기기에 업데이트한 뒤, Google 세션·선택 장부·기존 메모리 장부 응답이 모두 유지됨을 대조했다. 플러그인이 등록됐지만 비활성이며 구매 화면이 노출되지 않는 것도 확인했다. 이는 Play 실제 청구 검증 결과가 아니다.

실제 구매 시험에 필요한 외부 준비는 Play의 `memoney_premium` / `annual` 연 상품과 한국 기준 연 2,000원 가격 등록, Play 앱 서명에 맞는 OAuth·내부 테스트 설치, Android Publisher 서비스 계정 권한·서버 비밀 설정, 라이선스 테스트 계정(PD서) 등록이다. 아직 콘솔 상품 등록·운영 DB 스키마 적용·실제 청구는 수행하지 않았다. [Billing 통합 안내](https://developer.android.com/google/play/billing/integrate), [버전 기록](https://developer.android.com/google/play/billing/release-notes).

## 서버 구매 API 연결

`/api/billing/status`(GET)와 `/api/billing/verify`(POST)를 추가했다. `BILLING_ENABLED`는 기본적으로 false이며 비활성 상태 조회는 DB를 읽지 않는다. 활성 시에는 메머니 세션, 같은 origin, 요청 본문 크기와 필드를 검사하고 서버의 서비스 계정으로 Google 구매를 검증한다. 사용자 ID·프리미엄 플래그를 클라이언트가 지정할 수 없다. 사용자당 시간당 30회 검증 제한은 장부 입력 한도와 별개의 API 보호다.

서버 비밀 환경변수는 `BILLING_SERVICE_ACCOUNT_EMAIL`, `BILLING_SERVICE_ACCOUNT_PRIVATE_KEY`이며 Android Publisher 범위의 OAuth JWT 교환에 사용한다. 검증된 구매를 인증 DB에 기록한 후 구매 승인을 요청한다. 승인 응답만 실패한 경우 실제 결제 권한은 유지하고 복원/재검증으로 승인을 재시도한다. 결제 대기는 혜택도 승인도 부여하지 않는다. 실제 비밀 값과 운영 스키마는 아직 설정하지 않았다. 라이선스 시험 구매 허용은 명시적인 `BILLING_ALLOW_TEST_PURCHASES=true`로만 켠다.

인증/구매 API 검사와 기존 정책·저장 검사 합계 21건이 격리 SQLite/Google 모의 응답으로 통과했다. 실제 청구 성공을 검증한 것은 아니다. RTDN·실제 Play 상품·서비스 계정 권한과 환불/복원 검증을 마치기 전 운영 결제를 켜지 않는다.

## 다음 구현

1. 구현된 Play Billing 연결로 내부 테스트에서 실제 연 상품 조회·구매·복원을 확인한다. 메머니 로그인 계정과 Play 구매 계정이 같다고 가정하지 않는다.
2. 구현된 서버 서비스 계정 인증·구매 검증 API·구매 승인에 실제 권한을 설정하고, RTDN 수신·Google 재조회를 추가한다. RTDN 알림 종류만으로 혜택을 부여하거나 해제하지 않는다. 서비스 계정 비밀 키를 앱·Git·채팅에 넣지 않는다.
3. 인증 DB 스키마 검토·적용과 계정별 권한 조회. 운영 적용은 실제 결제 상품·서비스 계정·환불/복원 검증 뒤 진행한다. 서버 상태를 확인하지 못한 것을 신규 결제 성공으로 처리하지 않는다.
4. AdMob 보상형 광고와 서명된 서버 보상 검증. 광고 이벤트 ID의 재전송으로 이용권이 중복 발급되지 않게 한다. 광고 테스트에는 테스트 광고 단위만 사용한다.
5. 거래 저장과 이용량 집계 연동. 성공한 고유 작업만 차감하고, 저장 실패·응답 유실·재시도·여러 기기 동시 등록을 기존 operation ID로 대조한다. 여러 물리 DB의 개인/공유 장부를 사용하는 계정의 이용량을 단순 조회 후 증가 방식으로 구현하지 않는다. 중간 실패의 예약/확정/재조정까지 검증한 뒤 활성화한다.
6. 기기 로컬 모드·오프라인 동작, 날짜/시간대 경계, 정기 자동 발생·할부·가져오기·백업 복원의 집계 범위를 확정한다. 제한 때문에 정상 정기 거래가 누락되거나 복원 데이터가 잘리지 않도록 한다.
7. 구매·갱신·유예·환불·만료·재로그인·앱/웹 권한 동기화와 공유 장부 호스트 변경을 분리된 시험 계정/장부로 확인한다.
