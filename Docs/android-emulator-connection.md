# Orca 에뮬레이터 연결 복구

## 세로 폰과 펼친 화면 동시 표시

`npm run android:unfolded`는 별도 `Memoney_Unfolded_4_3` AVD를 찾아 부팅하고, 해당 기기에만 2048×1536·320dpi 화면을 적용한 뒤 별도 scrcpy 창을 연다. Medium_Phone의 해상도·회전·Google 계정·장부와 Orca 선택은 변경하지 않는다. 새 기기는 기존 APK를 설치했으며 우선 로컬 장부로 열어뒀다. 같은 클라우드 장부를 보려면 새 기기에서 별도로 로그인한다.

현재 에뮬레이터 37.1.11에서는 첫 사용자 지정 하드웨어 설정으로 실행한 새 기기가 부팅 초기에 종료됐다. 기존 폰과 같은 하드웨어 기본 설정으로 부팅한 뒤 새 기기에만 `wm size`·`wm density`를 적용하는 구성을 검증했다. 이는 접힘 센서가 있는 기기가 아니라 펼친 화면의 배치를 위한 별도 가상 기기다.

창 표시 도구는 공식 Genymobile scrcpy 5.0.1 Windows 배포본이며 GitHub 릴리스의 SHA-256 digest와 다운로드 파일을 비교했다. 파일은 무시 경로 `.android-tools/scrcpy-5.0.1/`에 보관한다. 재실행 도구는 창이 이미 있으면 중복 생성하지 않으며 앱 데이터를 초기화하거나 APK를 새로 빌드하지 않는다.

## 기존 미디움폰 연결

프로젝트 터미널에서 `npm run android:connect`를 실행한다. 이미 정상 부팅된 `Medium_Phone`이면 그대로 현재 작업공간의 Orca 에뮬레이터 화면에 연결한다. AVD 이름은 ADB shell의 기기 속성으로 확인하고, 기기 목록과 부팅 완료 상태를 모두 검사한다.

기기가 꺼져 있으면 소프트웨어 그래픽·스냅샷 없는 부팅으로 기존 AVD를 실행한다. 앱 데이터·Google 계정·장부는 지우지 않는다. 시작한 지 90초 미만인 프로세스는 부팅을 기다린다. 오래 응답하지 않는 경우 `Medium_Phone` 명령줄과 프로세스 생성 시각을 재검증한 뒤 해당 프로세스만 한 차례 종료하고 다시 부팅한다. 종료가 확인되지 않으면 중복 기기를 실행하지 않는다.

2026-10-15 확인한 장애에서는 Orca 재시작 뒤 남은 `qemu-system-x86_64-headless.exe -avd Medium_Phone -no-window`가 ADB `offline` 상태였다. Orca의 기기 목록에는 종료 상태로 표시돼 단순한 선택 해제로 보일 수 있었다. 해당 멈춘 AVD 프로세스만 수동으로 종료하고 기존 데이터를 유지한 부팅 후 `sys.boot_completed=1`, ADB `device`, Orca `attached=true`를 확인했다.

## Windows 로그인 후 자동 연결

2026-10-21 사용자 요청으로 매번 수동 복구하는 문제를 줄이기 위한 자동 연결 도구를 추가했다. Orca 자체의 연결 복원 코드는 변경하지 않는다.

`scripts/android-emulator-startup.ps1 -Install`은 현재 사용자의 시작프로그램 폴더에 `Memoney Android Auto Connect.lnk`를 등록하고 창 없는 연결 도구를 실행한다. Windows 로그인 후 Orca가 준비될 때까지 기다린다. 이후 미디움폰의 ADB 응답·실제 부팅 완료를 확인하고 이 작업 공간에 연결한다. Orca 실행 세션이 바뀌면 다시 연결하며, 확인 주기는 20초다. 다른 작업 공간으로 화면 초점을 강제로 옮기지 않는다.

- 정상 기기는 재부팅하거나 초기화하지 않는다. 부팅이 필요한 경우 미디움폰만 실행하고 메머니 앱을 연다.
- 미디움폰만 복구한다. 펼친 폴드 기기·실제 휴대폰·다른 에뮬레이터·Orca 프로세스·ADB 서버는 종료하지 않는다.
- 실패 시 5분 간격을 두고 재시도한다. 연속 재부팅을 방지하며, 권한·도구 오류를 기기 고장으로 간주하지 않는다.
- 중복 실행은 프로세스 종료 시 자동 해제되는 Windows named pipe로 방지한다. 이전 부팅의 PID 파일 때문에 새 실행이 막히지 않는다. 기록은 Git 무시 경로 `android/build/emulator-autoconnect.log`에 남긴다.
- 해제는 `scripts/android-emulator-startup.ps1 -Remove`다. 이 도구가 만든 바로가기만 제거하고 실행 중인 연결 도구에 종료를 알린다. 기기 데이터는 유지한다.

검증: `node --test scripts/android-emulator-runtime.test.mjs`의 9개 테스트로 정상 연결 유지, 진행 중인 부팅, 기기 없음, 멈춘 프로세스 복구, 종료·생성 실패, 프로세스 식별 변경, 중복·반복 실행 방지를 확인했다. 실제 멈춘 기기의 한 차례 재부팅과 `Attached emulator-5554` 기록, 시작프로그램 등록, 창 없는 도구 실행, 두 번째 실행의 중복 방지도 확인했다. 실제 Windows 재로그인 후 자동 실행은 다음 재부팅에서 최종 확인해야 한다.
