# 데이터 동기화 규칙

MyWallet의 기준 저장소는 Cloudflare D1이다. 브라우저 localStorage와 Wrangler 로컬 D1은 검토와 복구를 위한 캐시일 뿐이며, 기준 데이터로 간주하지 않는다.

2026-10-13 사용자 요청으로 추가한 **계정 없는 기기 모드(`/guest`)**는 예외다. 이 모드를 명시적으로 선택하면 `memoney:guest:<id>:` 저장 공간의 localStorage가 해당 기기 장부의 기준 저장소다. 기존 웹 장부·계정별 캐시를 가져오지 않고, 로그인한 공유 장부의 D1 우선 규칙은 유지한다.

2026-10-21 최신 확정 정책: Android/웹은 같은 인증·개인·공유 DB와 계정별 개인 UUID를 사용한다. 계정의 최초 Google 로그인 세션에만 비어 있는 개인 장부로 로컬 기록을 한 번 초기 이전할 수 있다. 이미 데이터가 있으면 서버 개인 장부로 전환하고 합치지 않는다. 공유 장부는 자동 이전 대상이 아니다. 로컬 원본은 보존하고, 재로그인/다른 기기/초기화/복구로 자격을 다시 만들지 않는다. 계정별 최초 처리·동시성·API·활성화 계약은 [최초 이전 구현](personal-onboarding-contract.md)을 따른다. 과거 문서의 반복 합치기와 웹 DB 분리 유지 설명보다 이 규칙이 우선한다.

- 기기 모드에서는 데이터 API를 네트워크로 호출하지 않는다. 거래·자산 등의 변경은 로컬에 기록한 뒤 성공을 반환하며, 저장 실패를 숨기지 않는다.
- 최초 로그인 자격은 공통 인증 서버의 최초 세션, 완료 여부는 개인 금융 DB의 계정/장부 메타데이터로 영속 관리한다. 기기별 플래그로 판단하지 않는다.
- 초기 이전은 빈 상태 재확인·전체 INSERT·완료 표식을 개인 금융 DB의 한 트랜잭션에서 처리한다. 레코드별 반복 업로드와 선택한 공유 장부에 합치기는 제거한다. 대상이 바뀌면 중단한다.
- 기존 서버 기록·설정·복구 이력이 있으면 로컬 기록으로 교체하지 않는다. 초기화 후에도 최초 처리 메타데이터를 보존한다.
- 자세한 범위와 개발 앱의 실행 조건은 [기기 모드 안내](android-local-mode.md)를 따른다.

## 기준

- 원격 D1의 `settings.updatedAt`이 서버 데이터의 기준 시각이다.
- localStorage의 `updatedAt`은 로컬 캐시가 가진 데이터 시각이다.
- `mywallet:v2:pendingSyncAt`이 있을 때만 localStorage를 "서버에 아직 반영되지 않은 로컬 수정"으로 본다.
- pending 플래그가 없는 localStorage는 오래된 캐시일 수 있으므로 D1을 덮어쓰면 안 된다.

## 앱 시작 시

- D1에 데이터가 있으면 기본적으로 D1 데이터를 적용한다.
- localStorage에 pending 플래그가 있고, 그 시각이 D1 `updatedAt`보다 최신일 때만 localStorage를 D1에 업로드한다.
- D1 적용 직후 React state가 바뀌어도 사용자 수정으로 취급하지 않는다.
- 서버 데이터 적용만으로 새 `updatedAt`을 만들거나 D1에 다시 POST하면 안 된다.

## 사용자 수정 시

- 거래, 자산, 계획, 카테고리, 정기기록 등 사용자가 데이터를 바꾸는 순간에만 새 `updatedAt`을 만든다.
- 수정 내용은 먼저 localStorage에 저장하고 `mywallet:v2:pendingSyncAt`을 기록한다.
- D1 저장이 성공하면 pending 플래그를 제거한다.
- D1 저장이 실패하면 pending 플래그를 남겨 다음 실행 때 재시도할 수 있게 한다.

## 금지

2026-10-21 장부 초기화·복구의 승인된 예외: [장부 복구](ledger-recovery.md)에 따라 서버 전체 보관본 검증과 원본 변경을 같은 금융 DB 트랜잭션에서 처리한다. D1 우선순위는 유지한다. 세대가 다른 기기의 저장·이관은 차단하고 보류 원본을 기기에 따로 보관한다. 계정 없는 로컬 장부만 새 세대 저장 키와 포인터를 사용하며, 이전 키를 새 장부로 자동 합치지 않는다.

- 단순 조회, 화면 진입, 서버 데이터 로드, 캐시 복원만으로 `updatedAt`을 갱신하지 않는다.
- pending 플래그가 없는 로컬 데이터로 원격 D1을 덮어쓰지 않는다.
- 일부 필드만 들어있는 payload로 D1 전체 데이터를 교체하지 않는다.
- 검토용 로컬 D1을 원격 최신 데이터보다 우선하지 않는다.
