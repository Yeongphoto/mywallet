# 웹앱 호스팅 시 로고 변환 지침

## 확인된 기준

2026-10-06 사용자가 현재 Memoney 상태를 정상으로 확인했다. 기준 커밋은 `aa0d66f`이며, WORKROOM의 실제 배포 구성을 비교해 적용한 결과다. 이 기록은 해당 삼성브라우저·기기 환경에서의 확인이며 모든 플랫폼의 동작 보장은 아니다.

문제는 세 화면으로 나누어 판단한다.

1. 홈 화면의 설치 아이콘: 축소된 사각형과 흰 바탕·테두리 여부.
2. 실행 직후 네이티브 스플래시: 브라우저가 설치 메타데이터로 만드는 화면. 앱 HTML/CSS 수정으로 직접 제어할 수 없다.
3. 웹 초기 로딩·React 로딩·동기화 화면: 앱이 그리는 화면. 밝기, 흐림, 크기와 전환 연속성을 확인한다.

## 설치용 로고 제작

- 원본 벡터가 있으면 기존 경로를 재사용한다. 없다면 원본 PNG의 알파 경계를 자동 추출한다. 손으로 다시 그리거나 생성형 이미지로 재해석하지 않는다.
- 윤곽선·눈·입과 선 사이의 투명한 틈을 보존한다. 얼굴 내부를 흰색으로 메우지 않는다.
- 검은 배경에서 사용하는 현재 표식은 흰 경로와 투명 배경이다. SVG 안에 `<image>`·`data:image`로 PNG를 넣지 않고, 사각 배경·테두리·필터를 추가하지 않는다. 파일 확장자만 SVG인 래스터 포장은 순수 벡터와 다르다.
- 적응형 아이콘의 중앙 안전 영역 안에 원본 전체가 들어가도록 **균일하게** 배치한다. 이 고양이는 기존 0.89 배율을 사용한다. 이 수치나 고양이의 다섯 윤곽 개수를 다른 로고에 일괄 적용하지 않는다.
- PNG→SVG 변환은 안티앨리어싱까지 픽셀 동일하다고 주장하지 않는다. 실제 표시 크기와 화면 배율에서 원본과 비교하고 오차를 기록한다.

현재 파일은 `public/memoney-mark-v1.svg`, 생성기는 `scripts/trace-cat-artwork.mjs`다. 외곽·얼굴 내부의 구멍·두 눈·입의 다섯 닫힌 윤곽을 원본 `public/logo.png`에서 추출한다. 재생성한 결과는 `apply_patch`로 새 버전 파일에 반영하고 기존 버전 파일을 덮어쓰지 않는다.

## 매니페스트·폴백 구조

현재 확인된 순서를 유지한다.

```json
"icons": [
  {
    "src": "/memoney-mark-v1.svg",
    "sizes": "any",
    "type": "image/svg+xml",
    "purpose": "any maskable"
  },
  {
    "src": "/mewallet-v1-192.png",
    "sizes": "192x192",
    "type": "image/png",
    "purpose": "any"
  },
  {
    "src": "/mewallet-v1-512.png",
    "sizes": "512x512",
    "type": "image/png",
    "purpose": "any"
  }
]
```

favicon과 `apple-touch-icon`은 같은 192px PNG 폴백을 사용한다. SVG에는 내장 래스터·불투명 배경이 없어야 한다. PNG 폴백에는 `maskable`을 추가하지 않는다. `sizes`는 홈 아이콘·스플래시 전용 용도를 강제하는 속성이 아니므로 크기만으로 둘을 분리하지 않는다.

현재 매니페스트는 `/memoney-v1.webmanifest`다. 과거 매니페스트 URL도 같은 이름·아이콘 구성을 제공한다. 이름 변경과 아이콘 변경을 섞지 않으며, `id`, `start_url`, `scope`, localStorage 키와 금융 데이터는 로고 작업 범위에서 유지한다.

## 웹 로딩은 별도 유지

현재 로딩은 `public/mewallet-loading-v2.js`와 `src/LoadingGlyph.tsx`가 원본 투명 PNG를 `drawImage`로 복사하는 공통 캔버스 렌더러다. DPR에 맞춰 캔버스 해상도를 설정하고 `source-in`으로 기존 알파 픽셀만 흰색으로 표시한다. 눈·입·투명한 틈은 그대로 남는다.

설치 로고를 바꿀 때 이 렌더러를 새 SVG로 자동 교체하지 않는다. 초기 HTML·React·동기화의 크기를 맞추고, 테마 CSS가 다시 흐림 필터를 적용하지 않는지 검사한다. 검은 배경 문제를 피하려고 요청 없이 흰 배경으로 바꾸지 않는다.

## 피해야 할 실패 사례

- PNG `maskable` 추가: 홈 아이콘을 고치려다 삼성 네이티브 스플래시의 흰 사각형이 재발했다.
- 192px `any maskable`과 512px `any` 분리: 삼성에서 네이티브 스플래시가 작은 maskable 아이콘도 선택해 실패했다.
- 검은 사각 PNG를 SVG 안에 넣고 모서리만 투명하게 처리: 사용자가 홈 아이콘 테두리가 계속 생긴다고 확인했다.
- 데스크톱 미리보기·빌드 통과만으로 삼성 설치 화면까지 해결됐다고 보고하는 것.
- 설치 메타데이터 갱신을 위해 앱 삭제·사이트 데이터 삭제·브라우저 보안 설정 변경을 자동 수행하는 것.

## 검증·호스팅

1. `npm run build`와 `git diff --check`를 통과시킨다.
2. `node scripts/check-vector-artwork.mjs "<Chromium 또는 Edge 실행 파일>" "<검증 URL>"`로 눈·입·투명 영역, 중앙 안전 영역, 실제 표시 크기의 변환 오차를 확인한다.
3. `node scripts/check-loading-rendering.mjs "<브라우저 실행 파일>" "<검증 URL>"`로 초기·React 로딩과 DPR 1·2·3, 테마별 회귀를 확인한다.
4. 변경한 아이콘은 새로운 버전 URL을 사용한다. 매니페스트·HTML 링크·서비스 워커 프리캐시·캐시 버전·헤더·검사를 함께 갱신한다. 기존 설치 식별자와 데이터를 유지한다.
5. 실제 배포 주소에서 HTML이 새 매니페스트를 참조하는지, SVG 응답이 HTML 폴백이 아닌 `image/svg+xml`인지, 매니페스트 JSON과 서비스 워커 캐시 버전이 올바른지 확인한다. HTTP 200만으로 파일 존재를 판정하지 않는다.
6. 삼성 실기기에서 동일한 설치의 홈 아이콘·네이티브 스플래시·웹 로딩을 함께 확인한다. 설치 메타데이터가 갱신됐는지도 구분하며, 데이터 삭제를 전제로 검증하지 않는다.

## 다른 작업에 전달할 지시문

> 원본 로고의 윤곽과 내부 디테일·투명한 틈을 보존한 배경 없는 순수 벡터 SVG를 만들어라. PNG를 SVG 안에 넣거나 손으로 다시 그리지 마라. Memoney/WORKROOM에서 확인된 구조처럼 투명 SVG를 매니페스트 첫 아이콘의 `sizes: any`, `purpose: any maskable`로 두고, 192·512 PNG는 `any` 폴백으로 유지하라. PNG maskable과 크기별 용도 분리를 사용하지 마라. 원본과의 변환 오차를 측정하고, 기존 웹 로딩 렌더러·검은 배경·앱 식별자·데이터 키는 보존하라. 빌드와 실제 배포 응답, 삼성의 홈 아이콘·네이티브 스플래시·웹 로딩을 모두 검증하라. 다른 로고·기기에서도 동일 결과가 보장된다고 주장하지 마라.
