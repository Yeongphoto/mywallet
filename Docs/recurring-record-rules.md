# 정기기록 규칙

정기기록은 장부에서 거래를 등록하거나 수정할 때 `매달 정기 기록으로 등록` 체크박스를 켜서 만드는 자동 반복 기록이다. 일반 거래 목록이나 정기기록 관리 목록에서 별도로 수동 생성하는 기능이 아니다.

## 핵심 동작

- 사용자가 장부에서 거래를 등록하면서 정기기록을 체크하면, 입력한 날짜의 거래는 즉시 장부에 저장한다.
- 동시에 같은 날짜의 `일(day)`, 구분, 금액, 내용, 카테고리, 자산 정보를 가진 반복 규칙을 만든다.
- 반복 규칙은 입력한 거래의 다음 달부터 매달 같은 일자에 자동 거래를 생성한다.
- 말일이 짧은 달에는 해당 달의 마지막 날에 생성한다. 예: 31일 규칙은 2월에 28일 또는 29일로 생성한다.
- 자동 생성된 거래는 기존 장부 거래와 같은 실제 거래 내역이다.

## 생성·저장 및 식별자 보호 (2026-10-21 수정)

- 제목·금액·카테고리가 같아도 다른 규칙의 거래 ID나 `recurringRuleId`를 바꾸지 않는다. 특히 다음 달 시작 규칙의 최초 수동 거래를, 이번 달 활성화된 동명 규칙으로 재연결하지 않는다.
- 발생 ID는 기존 `rec_<규칙 ID>_<YYYY-MM>` 형식을 유지한다. 같은 ID 또는 **같은 규칙으로 명시적으로 연결된 같은 달 거래**가 있으면 추가하지 않는다. 기존 UUID와 수정된 내용은 그대로 보존한다.
- 클라우드는 `PATCH /api/data {op:'recurring.generate', timeZone:'Asia/Seoul'}`로 도래한 거래를 저장한 뒤 화면에 반영한다. 서버는 현재 시각과 유효한 IANA 시간대에서 기준일을 구한다. 클라이언트가 미래 `throughDate`를 보내도 사용하지 않는다.
- 한 번에 최대 40건을 처리한다. 발생 행, 증분 동기화 이력, `settings.updatedAt`은 같은 금융 DB batch로 커밋한다. 각 INSERT 직전에 현재 규칙의 일자·시작/종료 월, 동일 발생/연결 거래 및 삭제 표식을 재확인한다. 두 기기 경합·응답 유실 재시도는 기존 행을 덮어쓰거나 증분 이력을 중복 생성하지 않는다. 초기화/복구 세대 보호도 동일하게 적용한다.
- 생성할 기록이 없으면 금융 행·동기화 이력·`updatedAt`을 갱신하지 않는다. GET 조회는 거래를 생성하지 않는다.
- 로컬 모드는 같은 일정 계산을 쓰고, 로컬 원본과 생성 기록을 한 번의 저장으로 확정한다. 오프라인에서도 동작하며 금융 네트워크 요청은 하지 않는다.
- 앱 시작, 규칙 변경, 날짜 확인 주기(1분), 다시 화면에 돌아왔을 때, 네트워크 복구 때 누락 발생을 확인한다. 앱을 닫아 둔 동안 실행되는 별도 스케줄러는 이번 변경에 포함하지 않는다.
- 규칙 생성·수정 API는 `transaction_time`을 보존하고, 이미 생성된 거래의 시간은 규칙 변경만으로 덮어쓰지 않는다.
- 날짜를 바꿔 새 규칙을 만드는 경우 이전 활성 규칙을 따로 중단해야 한다. 이미 납부한 거래는 유지하고, 불필요한 이전 규칙의 발생은 명시적인 삭제 표식으로 제외한다. 동명 규칙을 임의로 합치거나 삭제하지 않는다.

검증: `npm run check:recurring`은 격리 SQLite/로컬 저장에서 동명 규칙 오연결, 19일 일정 전환, 말일·윤년·미래 날짜, 중단/삭제, 재시작·경합·재시도·중간 실패 롤백·세대 변경·시간 보존을 확인한다.

`node scripts/check-recurring-ui.mjs`는 실제 App과 격리 SQLite API를 연결하여 날짜 전환 후 화면 복귀, 서버 저장 및 새로고침 후 유지, 원래 거래 ID/규칙 연결 보존을 확인한다.

## 관리 목록의 역할

- 정기기록 관리 목록은 반복 규칙을 확인하고 중단/삭제하는 관리 화면이다.
- 관리 목록에 `거래 등록` 같은 수동 생성 버튼을 두지 않는다.
- 진행 중인 규칙에는 `이달부터 끊기`만 제공한다.
- `이달부터 끊기`를 누르면 선택된 달까지는 유지하고, 다음 달부터 자동 생성을 중단한다.
- 중단된 규칙에만 `목록 삭제`를 제공한다.
- `목록 삭제`는 반복 규칙만 관리 목록에서 제거한다. 이미 장부와 달력에 생성된 기존 거래 내역은 삭제하지 않는다.

## 금지사항

- 정기기록 ON/OFF를 기존 거래의 존재 여부와 섞어서 처리하지 않는다.
- 진행 중인 정기기록 규칙을 바로 삭제할 수 있게 만들지 않는다. 먼저 끊기 상태가 되어야 한다.
- 정기기록 관리 목록에서 과거 거래 내역을 삭제하지 않는다.
- 자동 생성 거래의 ID, `recurringRuleId`, `deletedRecurringTxs` 보존 규칙을 임의로 바꾸지 않는다.
- 저장 로직 변경 시 `transactions`, `recurringRules`, `deletedRecurringTxs`가 함께 보존되는지 확인한다.

## 수정 전 확인

정기기록 관련 코드를 수정하기 전에는 이 문서를 먼저 확인한다. UI를 바꾸더라도 위 동작은 유지해야 한다.
