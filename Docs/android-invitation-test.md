# 공유 장부 초대 테스트 APK

최신 APK 0.3.0의 공유 장부 생성·복사·진행률·초대는 [공유 장부 생성 테스트](android-shared-creation-test.md)를 따른다.

2026-10-14 후속 요청으로 기존 웹 DB와 분리한 개인 장부 테스트로 전환했다. APK 0.2.2부터 사용하는 DB와 현재 지원 범위는 [개인 장부 테스트](android-personal-test.md)를 따른다. 아래는 이전 공유 초대 테스트 구성의 이력이다.

2026-10-14 · `android_dev` · 개발 앱 `com.mywallet.dev`

## PC 없이 사용하는 최신 테스트 버전

2026-10-14 후속 요청으로 **HTTPS 서버에 직접 연결하는 테스트 APK(0.2.0-test, versionCode 2)**를 만들었다. 아래 PC/USB 방식은 이전 localhost APK의 안내로 보존한다. 최신 APK에는 PC 실행·USB 연결·ADB reverse가 필요 없으며 인터넷 연결이 필요하다.

- 앱 서버: `https://memoney-android-test.pages.dev`.
- 인증·초대 DB: 새로 만든 `memoney-android-test-auth`. 기존 `mywallet-db` 스키마를 수정하거나 금융 행을 복사하지 않았다.
- 소유자는 이전에 검증된 Google issuer/sub 및 사용자·장부 UUID를 유지해 등록했다. 세션·토큰·로컬 금융 데이터·상대방 권한은 이전하지 않았다.
- 실제 금융 API는 세션·membership 검사를 거친 뒤 기존 웹 원본에 연결한다. 기존 웹앱 배포는 그대로이며, 기존 익명 웹 경로가 남는다는 호환 기간의 한계도 유지한다.
- APK의 앱 ID와 debug 서명은 유지하고 버전 번호를 올렸다. 이전 APK를 삭제하지 않고 업데이트로 설치한다.
- 네트워크 오류는 APK에 포함된 `android-unavailable.html`에서 표시하고 재시도할 수 있다. 스플래시가 오류 화면을 가리며 무한 대기하지 않는다.
- 원격 origin의 계정 캐시·기기 장부는 이전 localhost origin과 구분된다. 이전 origin의 로컬 데이터는 지우거나 자동으로 원격에 합치지 않는다. 이전 로컬 기록이 필요하면 백업·복원을 사용한다.

### 최신 초대 UI

로그인하면 먼저 가계부 첫 화면이 열린다. 공유 장부에 아직 참여하지 않은 계정은 로컬 첫 화면을 열고, 받은 초대가 있으면 **공유 장부 초대** 팝업을 표시한다. 팝업에는 장부 이름·권한과 **나중에 / 참여**만 둔다. 나중에를 누르면 membership을 변경하지 않는다. 참여를 눌러야 공유 장부를 연다. 장부 ID만으로 가입시키지 않으며 Gmail 계정 검증·만료·취소·중복 수락 규칙을 그대로 적용한다.

초대 목록은 서버가 검증한 현재 Google 계정의 이메일과 일치하는 초대만 반환한다. 수락은 초대 ID와 인증 계정으로 검사하므로 초대 링크를 붙여 넣지 않아도 받은 초대가 표시된다. 초대 링크를 열었을 때도 관리 화면 대신 로그인 → 첫 화면 → 팝업으로 이동한다. 초대 관리 페이지는 **설정 → 장부 옆 톱니**에서 직접 연다.

후속 수정: 로그인 성공 뒤 장부 권한 확인이 진행되는 동안 계정/초대 버튼 화면을 렌더링하지 않고 로딩에서 첫 화면으로 직접 전환한다. 설정의 **계정** 항목에 Google 로그인 상태와 로그아웃을 표시한다. 로컬 모드에서 계정 로그인·로그아웃을 해도 장부 모드와 로컬 기록은 유지한다. **연결 끊기**는 장부 전환이며 **로그아웃**은 서버 세션 철회다.

### 실제 확인

PC 개발 서버를 종료하고 에뮬레이터의 ADB reverse를 제거한 상태에서 실행·본인 Google 로그인·서버 세션 200·owner 권한·기존 금융 조회 200을 확인했다. 실제 상대방 초대는 생성하지 않았다. 에뮬레이터의 인터넷을 끊었을 때 로컬 오류 안내·재시도 버튼이 표시되고 로딩 overlay가 남지 않는 것을 확인했다. 인증·공유 검사 42건과 모의 받은 초대의 첫 화면 팝업·나중에·참여·3가지 화면 폭 검증을 통과했다.

재배포는 `npm run build` → `node scripts/prepare-hosted-test.mjs`로 생성한 별도 runtime 안에서 `wrangler pages deploy dist --project-name memoney-android-test --branch android_dev`를 사용한다. 기존 웹 프로젝트의 설정·`.wrangler` 상태를 정리하지 않는다. `auth-initialization.sql`은 신규 빈 테스트 DB에 한 번만 실행한 초기화 파일이며 재배포 때 다시 실행하지 않는다.

## 범위와 연결 조건

현재 공유 기록을 사용하는 기존 장부 UUID를 유지하며, 소유자의 Gmail 초대·editor/viewer 권한·초대 확인·명시적 참여·취소·참여자 제거를 구현했다. 새 빈 장부 생성과 여러 금융 장부 격리는 후속 단계다.

이 APK는 PC에서 실행하는 `http://localhost:5187` 개발 서버에 연결한다. 에뮬레이터 또는 ADB가 연결된 실기기로 테스트할 수 있다. APK 파일만 설치하고 PC 연결 없이 두 휴대폰에서 사용할 수 있는 버전은 아니다. 그 경우 별도 HTTPS 서버·Google 인증 origin·운영 전환 검증이 필요하다.

기존 공개 웹앱은 배포·DB 스키마·API를 바꾸지 않았다. 인증·초대 메타데이터만 별도 PC 시험 DB에 추가하며 실제 금융 기록은 기존 연결과 동일한 D1 원본이다. Google 계정의 콘솔 테스트 사용자 등록은 앱의 장부 접근권한을 자동으로 부여하지 않는다.

## 시작하기

PC에서 다음 서버를 유지한다.

```powershell
npm run auth:server
```

에뮬레이터에는 `npm run android:run`으로 설치한다. 실기기는 USB 디버깅을 허용하고 실제 기기 serial을 `adb devices`로 확인한 뒤 아래 명령의 `<기기 serial>`과 파일 경로를 바꿔 실행한다. 기존 앱을 삭제하거나 앱 데이터를 지우지 않는다.

```powershell
& "$env:LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe" devices
& "$env:LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe" -s '<기기 serial>' reverse tcp:5187 tcp:5187
& "$env:LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe" -s '<기기 serial>' install -r '<APK 절대 경로>'
& "$env:LOCALAPPDATA/Android/Sdk/platform-tools/adb.exe" -s '<기기 serial>' shell am start -n com.mywallet.dev/.MainActivity
```

같은 PC에 두 기기를 연결하면 각 serial에 같은 reverse를 적용한다. USB 연결이 끊기거나 PC 서버가 종료되면 개발 API를 사용할 수 없다. 기기 계정에 테스트할 Google 계정이 없으면 Android 설정에서 직접 추가한다.

## 두 계정 테스트

1. 본인 계정으로 Google 로그인한다. 기존 세션을 사용하고 있다면 장부 관리의 `계정 변경`으로 본인 계정을 다시 선택해 최신 Google 이메일 검증을 받는다.
2. **설정 → 환경 → 장부 옆 톱니(장부 관리)**를 연다. 장부 UUID, 소유자와 초대 입력이 표시된다.
3. 상대방 Gmail 주소를 입력하고 `함께 기록` 또는 `보기만`을 선택해 **초대 만들기 → 링크 복사**를 누른다. 자동 이메일·카카오톡 전송은 하지 않는다.
4. 같은 에뮬레이터라면 초대 링크를 보관한 뒤 **계정 변경**에서 상대방 Google 계정으로 로그인한다. 상대방 기기라면 같은 테스트 APK를 열어 로그인 화면의 `초대 수락`으로 장부 관리에 들어간다.
5. APK의 **초대 수락 → 초대 링크** 입력에 복사한 링크를 붙여 넣는다. 개발용 링크는 브라우저에서 열기보다 앱 입력에 붙여 넣어 사용한다. **초대 확인**을 누르면 대상 계정·만료·권한을 확인한다.
6. **참여**를 눌러야 membership이 추가되고 공유 장부가 열린다. Google 로그인이나 초대 확인만으로 장부를 열지 않는다. 로컬 기록도 자동으로 합치지 않는다.
7. 양쪽에서 같은 장부 UUID와 기존 기록을 확인한다. `보기만` 초대는 서버가 쓰기를 거부한다. 상대방의 참여를 제거하면 이후 공유 API 접근이 거부된다.

개인 테스트 이메일은 소스·APK·문서에 고정하지 않는다. 사용자가 입력하거나 Google 서버에서 검증한 이메일만 PC 시험 DB에 저장한다. 기존 소유자는 이미 검증된 사용자 UUID 연결을 사용하며 신규 가입자나 이메일 문자열로 기존 기록 소유권을 자동 배정하지 않는다.

## 초대 처리와 보존

- 링크는 7일 만료, 1회용 무작위 토큰이며 DB에는 SHA-256 해시만 보관한다. 다시 만들면 같은 대상의 미수락 초대를 취소한다.
- 수락 계정은 최근 10분 이내 서버 검증된 Google Gmail 이메일과 일치해야 한다. 오래된 인증은 다시 Google 인증하도록 안내한다. 외부 이메일 기반 Google 계정 초대는 이번 버전에서 지원하지 않는다.
- 초대 소비·membership 추가는 원자적으로 처리한다. 동일 계정의 동시 수락과 응답 재시도는 중복 참여자를 만들지 않는다. 참여자 제거 후 기존 수락 링크를 재사용할 수 없다.
- 초대 확인 이전에는 상대방에게 장부 ID·회원 이메일을 공개하지 않는다. 비소유자는 초대 목록이나 관리 동작을 사용할 수 없다.
- 초대 주소의 token은 읽은 뒤 주소에서 제거한다. 로그인 전후 연결에는 30분 수명의 sessionStorage 임시 상태만 사용하고, 수락 완료 시 지운다. 금융 백업에는 넣지 않는다.
- `연결 끊기`는 기존처럼 이 기기의 로컬 장부 선택이다. 회원 권한 해제와 다르다.
- 초대 테스트 서버는 명시적인 개발 환경·기존 고정 장부에만 활성화된다. 이 API를 추가했다고 운영 공유 인증이 배포된 상태로 보지 않는다.

## 검증

`npm run check:auth` 40건: 실제 SQLite·서명 토큰 검증·프로필 출처·권한·잘못된 계정·동시 수락·재시도·만료·취소·권한 철회와 기존 저장 회귀 검사를 통과했다. 브라우저의 격리 API 모의 환경에서 초대 생성·잘못된 계정 차단·미리보기·명시적 참여·3가지 화면 폭을 확인했다. 운영 금융 요청 쓰기는 0건이다. 실제 에뮬레이터에서 현재 계정의 장부 ID·소유자 초대 화면을 확인했다.

두 실제 Google 계정 간 초대 수락은 사용자가 APK에서 직접 수행할 단계다. 자동 검사를 실제 상대방 계정 로그인 성공으로 보고하지 않는다.
