# 계정 없이 쓰기와 설정에서 동기화

2026-10-13 사용자 요청으로 Android 개발 브랜치에 추가했다.

## 사용 방법

- 로그인 화면의 **로컬 장부**로 기기 장부를 연다. **설정 → 환경 → 장부** 드롭다운에서 **공유 장부 / 로컬 장부**를 선택한다. 로그인 후에도 로컬 장부를 선택할 수 있다. 전환은 기록을 합치거나 로그아웃하지 않으며, 처음 사용하는 로컬 장부는 비어 있다.
- 거래, 자산, 계획, 카테고리, 예산·표시 설정, 정기기록, 삭제한 정기거래, 카드 결제 이력은 해당 WebView의 localStorage에 저장한다. 다음 실행에도 기기 모드를 유지한다.
- 로컬 장부의 **설정 → 환경 → 장부 → 연결**에서 Google 로그인과 가계부 연결을 확인한다. 로그인만으로 업로드하지 않는다. 장부 선택과 연결 동작은 한 줄의 컨트롤로 표시하며, 선택 목록은 카드 크기를 바꾸지 않고 겹쳐 열린다.
- **공유 장부에 합치기**는 연결된 공유 장부에 기록을 추가한다. 합치지 않고 공유 기록을 보려면 장부 드롭다운에서 **공유 장부**를 선택한다. 로컬 원본은 유지된다.
- 공유 장부에서는 연결 버튼이 **연결 끊기**로 바뀐다. 이 버튼은 로컬 장부로 전환하며 Google 로그인·공유 기록을 유지한다. 데이터 삭제나 공유 구성원의 접근 권한 해제는 하지 않는다.
- **설정 → 데이터 → 로컬 백업 → 백업 / 복원**은 모든 필드와 카드 이력을 포함한 JSON 파일을 사용한다. Android에서는 시스템 파일 저장 화면에서 위치를 선택한 뒤 UTF-8로 저장한다. 복원은 선택한 파일의 건수를 확인한 뒤 별도 버튼으로 실행하며, 공유 장부에는 요청을 보내지 않는다. 새 기기 모드의 전체 CSV 백업에도 전체 원본을 추가해 카드 정보를 보존한다. 오래된 CSV에는 카드 정보가 없을 수 있으므로 완전한 복원에는 JSON 원본 백업을 권장한다.

로그인·로고·동기화 화면은 앱의 화면 모드와 디자인 테마를 따른다. 장부 전환 전후에도 동일한 테마를 사용하도록 외형 설정만 `memoney:appearance:v1`에 보관한다. 기존 로고 이미지를 그대로 사용하며 금융 데이터와 앱 식별자는 변경하지 않는다.

## 저장 경계

기기 모드는 `memoney:guest:<UUID>:`를 사용한다. 기존 웹의 `mywallet:*`, 로그인한 계정의 `memoney:user:<UUID>:ledger:<UUID>:`와 분리한다. 기존 기록을 자동으로 가져오지 않는다. Google 인증 쿠키가 남아 있어도 기기 모드의 금융 요청은 로컬 어댑터에서 처리한다.

로컬 행 변경과 중복 요청의 완료 기록은 하나의 localStorage 쓰기로 저장한다. 저장 공간 부족·잘못된 저장 데이터는 성공 또는 빈 장부로 처리하지 않는다. 기기 모드에서는 서버 데이터 조회·자동 동기화를 하지 않는다. 앱 삭제·데이터 삭제에 대비해 백업이 필요하다.

## 합치기 범위

거래·자산·사용자 카테고리·정기 규칙·삭제된 정기거래·카드 결제 및 사용자 카테고리 계획을 추가한다. ID와 참조는 새 가져오기 ID로 연결하고, 자동 정기거래의 `rec_<rule>_<month>` 관계를 유지한다. 자산의 기존 금액이 있는 오래된 백업은 기초잔액 거래로 보존한다.

**기존 공유 예산, 기본 카테고리의 계획과 환경 설정은 유지한다.** 기기의 값은 원본 백업과 가져오기 작업의 스냅샷에 남는다. 전체 DB 저장, 계획 전체 교체, 규칙 전체 교체 API를 사용하지 않는다.

기존 웹 API의 정기 규칙 생성/수정은 `time`을 저장하지 않는다. 따라서 시간이 있는 정기 규칙은 **첫 업로드 전 중단**한다. 기기 사용에는 제한이 없으며, 웹 API의 시간 지원이 추가되기 전까지 해당 기록의 합치기는 지원하지 않는다.

합치기 시작 전에 대상 계정·가계부, 원본, ID 매핑, 작업 목록을 저장한다. 저장 성공을 재조회하고 진행 위치를 기록한다. 응답 유실·앱 종료 후 같은 ID로 이어서 진행하며 기존 기록을 중복 추가하지 않는다. 대상 계정이 바뀌거나 가져온 기록이 다른 기기에서 변경됐으면 덮어쓰지 않고 중단한다. 중단된 작업을 재개하는 동안 기기 편집을 잠근다.

완료 후 공유 장부를 열며 기기 원본은 보관한다. 합치기를 완료한 뒤 다시 로컬 장부를 선택하면 별도의 새 기기 장부를 사용한다. 다른 Google 사용자에게 기존 공유 장부 접근을 자동으로 부여하지 않는다. 현재 개발 환경에 연결된 사용자·가계부에서만 공유 동기화를 사용할 수 있다.

## 개발 앱의 실행 조건과 검증

현재 APK의 시작 URL은 여전히 PC의 `http://localhost:5187/signin`이다. 화면을 처음 불러올 때 PC 개발 서버와 ADB 연결이 필요하다. 화면이 열린 뒤 기기 저장은 서버가 없어도 작동한다. 독립 실행 APK와 배포용 Google 인증 연결은 이후 포팅 단계에 포함된다.

`npm run check:auth`에서 실제 웹 데이터 핸들러와 메모리 SQLite로 추가/재시도/계정 변경/공유 예산 보존을 확인한다. 실제 운영 가계부에 시험 기록을 업로드하지 않는다. 기존 사용자 파일·`.wrangler` 상태·운영 스키마는 변경하지 않는다.

2026-10-13 검증: 웹·Android APK 빌드, 자동 검사 32건 통과. 에뮬레이터의 별도 시험 장부에서 실제 등록 화면으로 한글 거래 저장 → 화면 재로딩 → JSON 복원 경로를 확인했고 금융 네트워크 요청은 0건이었다. 강제 종료 후 재실행에서도 기기 모드와 기록을 확인했다. 시스템 파일 저장 화면으로 JSON을 Downloads에 저장하고 실제 파일을 파싱해 형식을 확인했다. 실제 Google 로그인 후 자동 업로드 없이 동기화 선택 화면으로 돌아왔고, 기존 공유 장부의 조회 결과가 웹 API와 동일한 것도 확인했다.

2026-10-14 검증: 웹·Android APK 빌드와 자동 검사 32건 통과. 격리된 브라우저에서 로그인 상태의 장부 드롭다운 전환·공유 기록 보존·테마 유지·로그인 화면의 6가지 테마 조합을 확인했다. 에뮬레이터의 별도 시험 장부에서 한글 거래 저장·재로딩·새 데이터 메뉴의 JSON 복원을 확인했으며 금융 네트워크 요청은 0건이었다.
