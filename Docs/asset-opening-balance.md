# 신규 자산 기초금액 보존

사용자가 첫 가이드 검수 중 발견한 저장 문제의 후속 수정을 승인했다.

원인은 현재 등록 화면이 기초금액을 `asset.amount`로 전송하고 `openingTransaction=null`을 보내는 반면, 로컬 처리기는 항상 기존 금액 또는 0을 사용하고 클라우드 INSERT도 0을 넣었던 것이다. 신규 자산의 이름은 저장되지만 입력 금액은 사라졌다.

- 직접 금액 방식: 로컬/클라우드 신규 자산 생성 시 유한한 `asset.amount`를 숫자로 저장한다. 수입·지출 거래는 추가하지 않는다.
- 예전 방식: 별도 `openingTransaction`이 있으면 자산 기본금액을 0으로 유지하고 그 거래를 기존대로 저장한다. 같은 금액을 두 번 합산하지 않는다.
- 자산 정보 수정은 기존 금액을 보존한다. 메모/이름 수정에 금액 변경을 섞지 않는다.
- 기존 0원 자산이나 거래를 스캔해 금액을 추측·덮어쓰지 않는다. 과거 유실된 입력 금액은 현재 기록만으로 복구할 수 없다.
- 로컬 장부의 저장 공간/세대/operation receipt/IndexedDB 완료 규칙과 클라우드 D1 우선 정책은 유지한다. 스키마/DB/사용자·장부 UUID를 변경하지 않는다.

검증은 메모리 SQLite와 격리 브라우저의 합성 장부만 사용했다. `node --test scripts/asset-opening-balance.test.mjs` 5건으로 로컬/클라우드 양수·0·음수, 조회/재실행, 메타데이터 수정, 중복 생성, 잘못된 금액, 예전 기초 거래, 로컬 백업 왕복, 저장 실패/트랜잭션 롤백을 확인했다. 실제 배포용 동결 금융 처리기에도 같은 5건을 적용해 통과했다. 기존 인증/공유/로컬 50건과 복구 6건, production 빌드 및 첫 가이드 UI 16개 화면 조합도 통과했다. UI 검사는 첫 자산에 입력한 130,000,000원이 재실행 후 그대로 남는지 확인하며 금융 네트워크 호출은 0건이다.

서버 반영은 `scripts/prepare-asset-opening-runtime.mjs`로 현재 배포본의 `server/wallet/legacy-data.ts`에서 신규 자산 INSERT의 금액 바인딩 한 곳만 바꾼다. 다른 금융 처리기·인증·정적 파일과 `wrangler.json`은 그대로 대조한다. 실DB SQL·데이터 보정·초기화·최초 이전/결제 플래그 활성화를 수행하지 않는다.
