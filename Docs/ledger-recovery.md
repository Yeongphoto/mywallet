# 장부 초기화·삭제 예약과 7일 복구

2026-10-21 구현. 기존 웹앱 DB에는 적용하지 않는다. `AUTH_LEDGER_RECOVERY=true`인 Memoney 배포의 격리된 금융 DB에서만 동작한다.

## 사용 방법

- 설정 → 데이터 → 장부 보관 및 복구에서 개인/로컬 장부를 초기화한다. 작업명을 직접 입력한 뒤 확인한다.
- 공유 장부는 호스트만 삭제를 예약한다. 모든 멤버의 이용이 중단되고 7일 동안 같은 장부 ID·권한으로 복구할 수 있다. 기간이 지나면 금융 데이터를 파기하고 소유 장부 생성 슬롯을 반환한다.
- 보관 목록에 생성 시각과 정확한 복구 기한을 표시한다. 복구하면 현재 기록도 먼저 별도 보관한다. 이전 보관본의 기한을 연장하지 않는다.
- Google 장부 변경은 서버가 소유권, Origin, 최근 15분 내 로그인, 변경 버전과 작업 ID를 확인한다. 재인증이 필요하면 기존 로그인 화면에서 계정을 다시 확인한다.
- **연결 끊기**는 여전히 로컬 모드 전환이다. 초기화·공유 탈퇴·삭제 예약을 하지 않으며 재연결에 7일 제한을 두지 않는다.

## 서버 보존과 동시 저장

`server/wallet/recovery-store.ts`, `recovery.ts`와 `/api/wallet/recovery`가 담당한다.

- 금융 DB에 보관본, SHA-256 manifest, 작업 응답과 장부 세대(generation)를 추가 테이블로 기록한다. 인증 DB와 금융 DB를 가로질러 금융 스냅샷을 복사하지 않는다.
- 거래(삭제 표식 포함), 자산, 계획, 모든 카테고리·설정, 정기 규칙, 삭제된 정기 거래 ID, 카드 정산, 정렬 revision, 작업 영수증, 변경 cursor의 **모든 열**을 함께 보존한다. 스키마의 열을 검사해 누락을 허용하지 않는다.
- 서버가 읽은 원본 전체의 해시와 원본 JSON 일치를 다시 검증한다. 보관본 기록, 원본 비우기/복원, 세대 변경을 같은 D1 batch 트랜잭션에서 실행한다. 어떤 문장이라도 실패하면 전부 롤백한다.
- 각 금융 쓰기의 실제 트랜잭션 안에도 세대와 active 상태를 검사하는 CHECK 제약 guard를 넣는다. 요청 입구에서만 검사한 뒤 경쟁 상태를 허용하지 않는다.
- 초기 상태에서는 이전 앱의 헤더 없는 쓰기를 허용한다. 첫 초기화/복구/보관 이후에는 새 세대 헤더가 반드시 필요하다. 오래된 앱·기기의 저장 및 cursor 재사용은 거부한다.
- 다른 기기에 이전 세대의 보류 변경이 있으면 먼저 기기 내 IndexedDB에 계정·장부·원본 캐시·큐를 함께 보관한 후 최신 장부를 연다. 설정의 ‘이전 변경 보관본 내보내기’로 내려받을 수 있다. 자동으로 새 장부에 재전송하지 않는다.
- 로컬→Google 이관 작업도 처음 읽은 대상 세대를 저장한다. 중간에 대상 세대가 달라지면 진행을 중단한다.
- UTF-8 JSON 원본 총량 1,500,000바이트를 초과하면 초기화를 거부한다. D1의 문자열/행 2MB 제한보다 여유 있게 제한하며 일부 데이터만 백업하고 진행하지 않는다. [Cloudflare D1 제한](https://developers.cloudflare.com/d1/platform/limits/)

## 만료와 예약 정리

- 서버 UTC 생성 시각부터 정확히 7×24시간이다. 복원 트랜잭션 실행 시 SQL 서버 시각으로도 만료 여부를 재검사한다.
- `memoney-recovery-cleanup` Worker가 매시 17분에 실행된다. `scripts/prepare-recovery-cleanup.mjs`는 검증된 `memoney-auth`, `memoney-personal`, `memoney-shared` binding만 생성한다.
- 만료 보관본의 JSON을 비우고 감사 메타데이터를 남긴다. 만료된 공유 장부는 guard가 포함된 트랜잭션으로 금융 행을 삭제한다. 복원되어 active가 된 장부는 삭제하지 않는다.
- 금융 파기가 성공해 expired가 된 후에만 인증 DB에 만료 이력을 기록하고 `created_shared_ledgers` 예약을 해제한다. 장부 UUID·원 소유권·참여 이력은 보존하지만 선택 목록에는 나오지 않는다. 중단 후 재시도해도 새 장부를 삭제하지 않는다.
- D1 호출 한도를 고려해 공유 장부 금융 파기는 실행당 1개, 슬롯 정리는 최대 5개씩 처리한다. 복구 기한은 작업 지연과 무관하게 즉시 만료되며 물리 파기는 이후 예약 실행에서 처리한다.

## 로컬 장부

- 서버 보장이 아니라 해당 기기의 IndexedDB에 전체 JSON과 해시를 보관한다. 저장 완료와 재독해 검증에 성공한 뒤에만 새 장부를 활성화한다.
- 최초 로컬 장부의 기존 키는 유지한다. 초기화/복구 시에만 `memoney:guest:<id>:recovery-generation` 포인터와 별도 세대 키를 추가한다. 데이터 생성 후 한 번의 localStorage 포인터 쓰기로 전환한다. 이전 코드가 옛 키에 기록해도 새 장부를 덮어쓰지 못한다.
- Web Locks로 로컬 쓰기·뷰 저장·파일 복원·복구를 직렬화하고 세대와 이관 작업을 검사한다. 안전한 저장소/잠금을 지원하지 않으면 초기화 버튼을 활성화하지 않는다. 용량 초과 시 원본과 활성 포인터를 유지한다.
- 로컬 기한은 기기 시각을 기준으로 하며 보관함을 열 때 만료본과 사용이 끝난 세대 키를 정리한다. 앱이 닫혀 있을 때 예약 파기를 보장하지 않는다. 앱/사이트 데이터 삭제, 기기 분실, 기기 시각 변경에는 서버와 같은 보장을 할 수 없다. 외부 JSON 파일 백업을 함께 안내한다.

## 검증

- `npm run check:auth`: 기존 인증·공유·로컬·이관 회귀 검사.
- `npm run check:recovery`: 메모리 SQLite의 독립 DB에서 전체 열 round-trip, 새 기록 사전 보관, 실패 롤백, 중복 작업, 오래된 세대 batch 차단, 권한·Origin·재인증, 7일 경계, 손상·용량 초과, 공유 파기·슬롯 재사용을 확인한다.
- `node scripts/check-ledger-recovery-ui.mjs`: 독립 브라우저 저장소와 모의 API로 실제 설정 UI의 확인 입력, 로컬 초기화/복구·용량 실패, 클라우드 세대 전환과 보류 큐 보존, 폴드 화면, 호스트/게스트 보관 화면을 확인한다.
- 실제 사용자 장부에 초기화·삭제·복구 요청을 보내 검증하지 않는다. 기존 웹앱 DB와 `.wrangler` 상태를 정리하거나 덮어쓰지 않는다.
