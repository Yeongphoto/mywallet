# 격리된 개인 장부 테스트

2026-10-18: 기존 데이터를 보존해 플랫폼 공통 이름의 메인 DB로 전환한다. 현재 연결 대상과 이전 절차는 [공통 운영 DB](main-databases.md)를 따른다. 아래 내용은 최초 격리 당시의 기록이다.

2026-10-14 사용자 확인: 현재 기록은 아직 공유하지 않은 개인 장부다. 기존 웹앱 DB와 분리한 복사본으로 테스트한다. 이전 테스트 배포의 단일 공유 장부 연결을 대체한다.

## 현재 구성

- 기존 웹앱과 `mywallet-db`의 금융 기록·스키마는 변경하지 않는다. 원본 DB는 읽기 전용 SQL 내보내기로 한 번 복사했다.
- 앱 테스트 금융 저장소는 별도 D1 `memoney-android-test-personal`이다. 인증·세션은 기존 테스트 인증 DB를 사용한다.
- 개인 장부에 새 UUID를 발급하고 본인의 검증된 Google 사용자 UUID에 owner로 연결했다. 다른 계정은 해당 개인 장부를 조회·수정할 수 없다.
- 기존 금융 API의 revision·operation 재시도·증분 동기화 로직을 테스트 DB에 직접 실행한다. 개인 테스트 모드에서는 기존 웹 `/api/data`로 금융 요청을 전달하지 않는다.
- 테스트 DB에 저장한 장부 ID 표식을 검사한다. binding 누락·잘못된 표식·운영 origin 혼합은 실패 처리하며 웹 DB로 우회하지 않는다.
- 거래·자산·계획·카테고리·정기 규칙·정기 제외 ID·카드 결제·설정·revision·동기화 이력을 보존했다. 삭제된 거래도 원본 테이블에 보존하며 화면에는 기존처럼 표시하지 않는다.
- 로컬 장부는 기존 기기 namespace를 유지한다. 로그인만으로 로컬 장부를 업로드하지 않는다. 이전 공유 장부의 캐시와 보류 변경은 새 개인 UUID로 옮기거나 자동 전송하지 않는다.
- 개인 장부에서 초대 생성·수락 API는 차단한다. 설정에는 `개인 장부`를 표시하고 관리 화면에 개인 장부 ID를 표시한다.

원본 웹과 테스트 앱은 복사 이후 서로 독립적이다. 앱에서 시험 기록을 수정해도 여자친구가 사용하는 웹의 기록에 반영되지 않는다. 반대로 웹에서 이후 추가한 기록도 이 테스트 복사본에 자동으로 들어오지 않는다.

## 다음 구현

**2026-10-14 업데이트:** 공유 장부 생성·개인 클라우드 장부 복사·빈 장부·이름 변경·장부 선택·초대를 구현했다. 진행률과 복사 재개를 포함한 최신 흐름은 [공유 장부 생성 테스트](android-shared-creation-test.md)를 따른다. 아래는 이전 개인 장부 전환 단계의 후속 계획이다.

개인 장부를 원본으로 `공유 장부 만들기 → 이름 → 개인 장부 복사하기 / 빈 장부 → 초대`를 구현한다. 공유 금융 저장소는 개인 장부와도 구분한다. 계정당 소유 공유 장부는 1개, 초대받아 참여하는 장부는 별개다. 현재 단계에는 이 생성 화면을 구현하지 않았다. 개인 장부의 Google 연결 해제 시 로컬 복사본으로 만드는 흐름도 별도 후속 작업이며, 현재 `연결 끊기`는 기존 로컬 장부 선택 동작이다.

## 재배포와 검증

`scripts/prepare-personal-test.mjs`는 최초 복사 준비용이다. 기존 파일과 테스트 기록을 덮어쓰지 않도록 새 파일 전용 쓰기를 사용한다. 생성한 금융·메타데이터 초기화 SQL은 지정된 새 테스트 DB에 한 번만 실행했다. 기존 `auth-initialization.sql`이나 복사 SQL을 다음 배포에서 재실행하지 않는다.

다음 배포는 `npm run build`, `node scripts/prepare-hosted-test.mjs`로 별도 runtime을 만들고 그 디렉터리에서 테스트 Pages 프로젝트에 배포한다. `.android-tools/personal-test-wallet.json`이 새 개인 장부와 금융 binding을 지정한다. 기존 웹용 Wrangler 설정으로 테스트 SQL을 실행하지 않는다.

원본 SQL과 테스트 DB를 다시 내보낸 SQL은 모든 금융 테이블의 전체 행·컬럼 비교에 사용한다. 금융 본문은 `android/build/`의 로컬 검증 파일에만 보관한다. 자동 검증은 `npm run check:auth`와 `node scripts/check-personal-test-copy.mjs`를 사용한다. APK 0.2.2는 기존 개발 앱에 업데이트 설치할 수 있으며 앱 데이터 삭제가 필요하지 않다.

검증 결과: 인증·저장 회귀 및 격리 검사 44건 통과. 모든 금융 테이블의 행·컬럼 복사 일치 확인. 설치한 에뮬레이터의 실제 Google 세션으로 새 개인 장부 조회와 시험 거래 등록·재시도·수정·409 충돌·삭제를 확인했다. 시험 거래는 테스트 앱에서 삭제했고 기존 웹 조회에는 나타나지 않았다. 로그인/로그아웃 및 로그인 직후 화면 전환 검사도 통과했다. 다른 실제 Google 계정의 로그인은 수행하지 않았으며, 개인 장부 접근 거부는 서버의 격리 테스트로 검증했다.
